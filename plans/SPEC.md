# VibeBridge：个人多项目 Agent CLI 工作台规格

状态：按当前 UI 原型逐项对齐第一版规格。创建流程、界面基准、初始排布取舍、取消草稿规则及增删面板的简化布局规则已同步；空间不足由用户主动调整大小，程序不承担专门兜底。技术栈、共用终端管理进程及配置文件／SQLite 分工已确认；手改配置文件重启生效，设置界面写回同一文件；主题在重启后统一应用，快捷键即时生效。第一版不另设普通终端面板。架构决策已收敛，直接启动、现有进程间故障检测、基础保存及输出处理边界已同步；命令环境接入、故障清理与可靠保存进入实施验证；用户已接受当前真实终端体验作为首版基准；该确认仅针对终端，外部 UI 继续遵循此前原型讨论的有效决议。终端网格尺寸保留为可读性参考。

适用范围：个人日常使用的 macOS 本地应用。

术语依据：[领域词汇表](./CONTEXT.md)。面板是工作台的界面单元，会话是 CLI 保存的对话，运行实例是一次实际运行，三者不可互换。

决策依据：[第一版决策地图](https://github.com/a1457139709/VibeBridge/issues/1)。整体前端界面已按用户确认的 UI 原型确定；导航页面打开方式、Agent 面板排列等操作与交互逻辑细节以已确认原型补齐，主体产品与技术决策保持不变，当前视觉及演变记录见 [UI 原型说明](./ui.prototype/README.md)。原型中的模拟运行、候选算法和未同步的旧阈值不作为正式产品验收结论。

## Problem Statement

用户需要同时处理多个项目，并在同一个项目中并行操作不同类型的 Agent CLI。现有做法依赖多个终端窗口或 tmux 等分屏工具，项目目录切换、Agent 启动和分屏整理需要额外操作。用户希望通过鼠标和快捷键完成这些工作，并保留各 CLI 原有的交互方式。

首次创建项目时，用户希望在一个简单的页面编辑项目名称和目录，手动选择窗口总数，再配置各类 Agent 的数量，分配合计必须等于总数，确认后直接进入自动排布的多面板工作区。创建页提供只读排布预览，无需选择或调整布局；进入工作区后再按需手动调整。日常使用需要按需增加和关闭面板，由程序自动排列。

工作台需要记住项目、面板配置与布局。历史对话由 CLI 保存，用户通过 CLI 自带的历史选择或恢复命令继续原会话。退出应用后，工作台启动的 Agent 不应继续占用资源。

## Solution

左侧为可折叠的项目导航，右侧为当前项目的 Agent 终端分屏。每个项目对应一个本地目录，其运行实例共享该目录。

点击添加项目直接进入统一的项目创建页，项目名称、项目目录、窗口总数与 Agent 数量分配在同一页编辑，最后统一确认。窗口总数默认三，各 Agent 数量初始为零，由用户手动分配。例如先选六个窗口，再分配两个 Claude Code、两个 Codex CLI、两个 pi，分配合计必须等于选定总数。确认后按数量创建面板、自动排布、保存配置，进入工作区并启动所选 Agent。第一版沿用现有自动排布，三个面板在空间允许时优先上方一个大面板、下方两个小面板，也可按可用空间采用其他平铺排列；固定形状和排列优化程度不作为验收门槛。用户发现排列不合用时，在工作区手动调整比例或交换位置。

进入工作区后，用户通过“＋”打开位于主窗口中央的“添加 Agent”大弹窗，点击 Agent 选项，在数量允许时新增并启动一个面板，也可直接关闭面板。第一版添加弹窗采用 B 的纵向列表，图标在名称左侧，背景仍可看到当前项目；项目导航独立采用 A 的默认展开侧栏。面板集合变化时自动排布；用户仍可调整相对大小、交换位置，程序自动保存布局。每个项目最多十个面板，所有面板平铺在布局区域内，布局区域不滚动。空间不足时由用户主动调整主窗口或面板大小。

当前接入 Codex CLI、Claude Code 和 pi 三种 Agent，三者同等支持。工作台使用本机已安装、登录并配置好的 CLI，所有 Agent 的设置集中在同一个设置界面。同一种 Agent 可在同一项目中并行运行多个实例。每个面板在创建时选择 Agent，不增加已有运行面板的原位类型切换功能。

工作台保存面板配置和布局；用户在 CLI 内手动恢复历史会话。重开应用后，直接进入上次退出时正在查看的项目，显示其保存的布局并自动启动已保存面板中的 CLI，无需逐个点击启动入口；其他项目在本次应用运行中首次切换到时自动启动，启动后切走仍继续运行，再次切回不重复启动。自动启动 CLI 后，由用户在 CLI 内手动恢复所需会话。

点击主窗口关闭按钮或主动退出时先确认。取消则保持全部运行实例；确认则保存面板与布局，结束工作台管理的全部运行实例及需要清理的子进程后退出。项目切换、最小化与临时放大面板均不结束其他实例。

## User Stories

1. 使用一个本地工作台管理多个项目和 Agent CLI，减少日常终端整理操作。
2. 使用本机已安装、登录和配置好的 Codex CLI、Claude Code 和 pi。
3. 在统一界面管理所有 Agent 设置，使用与本机终端一致的启动命令；启动失败时获得简洁提示。
4. 在同一项目目录中并行运行多个不同或相同类型的 Agent。
5. 在同一创建页编辑项目名称和目录、手动选择窗口总数，再通过加减号分配各类 Agent 的数量，查看只读排布预览，确认后统一进入工作区。
6. 按所选数量和可用空间自动排布面板，进入工作区后可手动调整比例或交换位置。
7. 通过“＋”打开主窗口中央宽敞的添加弹窗，选择 Agent 并新增面板，由程序自动安排空间。
8. 直接关闭面板以停止其中的运行实例，其余面板自动重新排列。
9. 随时调整面板大小和位置，由程序自动保存布局；项目切换与应用重开后保留安排。
10. 同屏查看最多十个面板，布局不滚动；必要时临时放大单个面板。
11. 从左侧导航切换项目，折叠后仍可通过窄栏切换；其他项目继续运行。
12. 保留原生 CLI 输入、输出及交互，在 CLI 内自行选择历史会话或执行恢复命令。
13. 让工作台记住面板配置和布局，不需要每次重新安排终端。
14. 通过鼠标及可自定义的应用内快捷键切换项目、面板和放大状态。
15. 使用柔和简洁的终端分屏界面，通过圆角细边框区分面板，通过选中高亮辨认输入目标。
16. 主窗口关闭和退出前确认；确认退出后结束全部项目中的运行实例，避免残留进程。

## Implementation Decisions

### 1. 决策状态与实现边界

产品行为以本规格汇总的已确认要求为准；用户后续明确的 UI 反馈与旧条款冲突时，逐项回写正文和验收要求。第一版采用导航 A、添加弹窗 B，依据[界面组合与终端网格决议](https://github.com/a1457139709/VibeBridge/issues/11#issuecomment-5943680621)。该决议中的 60 列 × 12 行按后续[确定创建、恢复和屏幕空间不足时的用户行为](https://github.com/a1457139709/VibeBridge/issues/13)保留为可读性参考，不再作为程序强制下限。技术组织和验证建议不代表已有实现或已通过兼容验收。

2026-10-05 用户澄清：“以 UI 为主”指采用已确定的整体前端界面，并以 UI 原型中已调整清楚的操作细节与交互逻辑补齐规格遗漏，不表示 UI 在主体决策上具有更高优先级。导航页面的打开方式和 Agent 面板排列等细微差异按这一边界对齐；页面排布与图标的剩余细修可在实现完成后继续完善，不因此重开整体界面方案。历史候选、已废弃行为和模拟逻辑仍按本文的证据边界处理。

初始排列交由用户按需手调及取消保留本次应用内草稿，见[确定 UI 优先的规格基准、初始排布与创建草稿](https://github.com/a1457139709/VibeBridge/issues/16)。空间不足由用户主动调整大小；此前的空间不足拒绝新增、网格强制下限和自动扩窗要求已被后续范围调整替代，保存布局及正常运行生命周期继续适用。

已确认采用 TypeScript + React、Electron、xterm.js 和 node-pty。全部项目共用一个独立终端管理进程，由其管理各面板的 PTY 与独立 Agent 运行实例。用户可手动修改的简单配置（例如默认布局、默认主题）放在本地配置文件；程序自动维护、供重启恢复的项目、面板与布局状态放在 SQLite。数据模型仍围绕项目、面板及布局组织。

Electron 便于复用 React 界面并通过 Node.js 接入本地 CLI；xterm.js 负责终端呈现与输入，node-pty 负责系统侧 PTY；共用独立管理进程用于隔离终端组件与主进程。文件与 SQLite 分别服务于可手改配置和程序状态。技术选择不等于真实终端兼容、资源占用或主进程故障清理已经通过验证，独立管理进程也不自动保证清理全部受管子进程。

交互延迟与依赖约束（2026-10-05）：沿用已确认技术栈，优先使用 DOM／xterm.js、Electron／Node.js 及 PTY 的现有 API。面板点击、焦点、鼠标位置、拖动和尺寸调整不通过启动 PowerShell、AppleScript、shell 命令或外部自动化软件实现；不为这些交互额外引入服务或技术组件。必要的操作系统 API、共用终端管理进程与 Agent CLI 本身不属于应排除的依赖。Agent 按解析后的程序路径、参数、项目目录和环境变量通过 PTY 直接启动，不额外套 shell，不预先引入 shell 别名／函数兼容层；从应用图标启动时的命令路径与必要环境变量仍需接入验证。此处“原生”指直接使用既有平台能力，不代表改选 Swift／AppKit 界面。

开发与正式运行共用同一套启动、交互、PTY 管理、持久化与清理实现，不维护两套运行逻辑，也不以开发用途为由加入阻塞启动的实验流程。debug 是同一代码路径上的诊断开关，只增加日志、耗时及错误上下文等信息；必要的额外诊断检查按需触发，不成为显示窗口或正常交互的前置条件，不替换真实业务行为。构建和原生模块编译属于运行前的构建／依赖准备步骤，不由应用启动流程自动执行。版本探测若仅用于诊断，按需异步执行，不在启动时串行等待。

上述约束同时适用于开发与正式运行：避免同步磁盘／进程操作阻塞交互，并以日常二至四个、峰值十个 Agent 下的连续输入、焦点切换、拖动与大量输出来验证响应。现有真实终端原型的串行 CLI 版本探测、启动时构建检查、同步主题写入及固定关闭等待是尚未按此约束整改的历史实现，不能作为开发版可长期保留的例外；目前没有端到端延迟测量，不能据此宣称无卡顿。

2026-10-02 的[终端方向阶段结论](https://github.com/a1457139709/VibeBridge/issues/14#issuecomment-5946050938)确认继续采用真实 PTY + xterm.js 呈现 Agent 原生界面，先通过[真实 Agent 视觉与交互验证](https://github.com/a1457139709/VibeBridge/issues/17)判断外观调整及是否需要重评引擎。技术栈已在后续讨论中确认；真实终端已接入独立体验原型，尚未接入正式工作台。用户反馈深色表现不错、浅色视觉错乱，并提供原生浅色截图作为参考。原型已清除 PTY 继承的 NO_COLOR 并使用 xterm WebGL 绘制块字符，修正可复现的颜色丢失和图标黑条；用户随后[确认主题生效规则](https://github.com/a1457139709/VibeBridge/issues/17#issuecomment-5951151858)：移除页面明暗切换按钮，主题由设置入口选择、重启应用后生效，不加入 Agent 自动主题同步；此前独立终端配色对照入口移除。用户随后[确认当前终端体验可以作为首版基准](https://github.com/a1457139709/VibeBridge/issues/17#issuecomment-5951788329)，本项体验决策完成；未逐项记录的兼容场景仍由正式实现验收，不视为已实测通过。

终端与外部 UI 的采纳边界：真实终端原型仅提供 Agent 面板内终端呈现与交互的实现基准。系统栏、项目导航、项目创建、添加 Agent、面板顶部与操作、布局及全局设置继续按原 UI 原型讨论的有效决议与本规格实现，包括导航 A、添加弹窗 B、应用级独立设置页面及后续已确认修订。真实终端实验的简化侧栏、直接添加按钮、固定格数、PID／网格显示、底部调试栏、体验记录和临时设置对话框不作为正式产品 UI。

终端输出通过当前运行中的滚动缓冲查看，不跨应用重启保存或回看。本地配置文件的格式、完整字段、可靠读写机制、SQLite 接入库和打包方案等由技术调查与实现细化。手改配置文件在重启后生效，不做自动监听；设置界面写回同一配置文件，主题重启后生效、快捷键即时生效，不另存 SQLite 覆盖值。

| 能力 | 职责 |
|---|---|
| 项目与 Agent 设置 | 项目目录、统一管理各 Agent 的设置、CLI 可用性检查 |
| 创建引导 | 同页编辑项目名称和目录、窗口总数与 Agent 数量分配、只读排布预览、分配合计校验、确认后批量创建与启动 |
| 布局与面板交互 | 动态增删、自动排布、手动调整、焦点与临时放大 |
| CLI 与运行管理 | 原生终端交互、启动、运行状态、关闭与退出清理 |
| 配置保存 | 项目、面板配置、布局、快捷键与外观设置 |

### 2. 身份与关系

- 一个项目对应一个项目目录，拥有一组面板及其布局配置。
- Agent 类型表示所使用的 CLI 工具；所有类型的设置在同一处统一管理，供各项目中的面板使用。
- 每个面板具有自己的身份与 Agent 配置。改变位置或尺寸时，其终端画面、输入目标和运行实例仍属于同一个面板。
- 一个面板承载一个运行实例；同一面板在不同时间可经历不同实例，例如应用退出后保留配置，下次重开时重新启动 CLI。应用正常运行期间，已启动的 CLI 结束则关闭对应面板。
- Agent 会话的保存、选择与恢复由 CLI 管理。
- 用户在 CLI 内执行历史恢复、新建或分叉操作，均使用原生 CLI 交互。
- 关闭面板会从当前布局移除它；再次新增面板可以选择任意已配置的 Agent 类型。更换 Agent 类型通过关闭面板后新增完成。

### 3. 项目创建引导

1. 用户点击项目导航中的添加项目入口，直接在右侧内容区进入统一创建页，保留系统栏和项目导航；隐藏工作区项目工具栏，取消已有项目高亮，并高亮添加项目入口。取消后恢复原项目工作区与高亮；点击已有项目则进入该项目。创建草稿按下述内存规则保留，切换页面不停止已有运行实例。
2. 在页内编辑项目名称和本地目录，不需要先确认目录再进入另一页。项目名默认随目录末级名称更新，用户手动命名后独立保留。
3. 先手动选择窗口总数，再通过各 Agent 条目的加减号分配数量。例如先选六个窗口，再分配 Claude Code × 2、Codex CLI × 2、pi × 2；同类 Agent 使用对应的 Agent 设置分别启动独立实例。分配合计必须等于选定总数才能确认创建，总数不由分配数量自动推算。
4. 页面同时展示只读的自动排布缩略图，随总数和 Agent 分配变化；不提供布局选择、比例拖拽或逐格分配。面板大小与位置在进入工作区后调整。
5. 用户确认后按配置创建面板并自动排布，保存项目配置、进入主要工作区并启动 Agent。用户可在工作区手动调整布局。

引导页采用居中的简洁单页，使用柔和背景、轻边框与留白。页面从上到下为：

- “创建项目”标题，以及可编辑的项目名称和目录，组成项目信息组。
- 分割线下为窗口配置组，依次显示只读自动排布缩略图、窗口数量、Agent 分配和分配进度。主工作台不显示排布缩略图。
- “窗口数量”区域，通过加减号手动设置总数。
- “分配 Agent”区域，各 Agent 条目在同一页逐行显示名称及数量加减控件。
- 分配进度，例如“已分配 4 / 6”，未满时提示“还需分配 2 个”；修改总数导致超额时，例如“已分配 6 / 4”，提示“多分配了 2 个”。
- 底部“取消”和“创建并启动”按钮；取消回到工作台，不创建项目或启动 Agent，保留本次应用运行中的项目名称、目录、窗口总数及 Agent 分配草稿，再次打开创建页继续填写。草稿只在内存中保留，不跨应用重启保存。

创建页沿用当前原型的层级与控件：内容最大宽度 440px，标题 22px / 600；输入框与底部按钮高 36px，数量行高 56px，步进器高 32px。预览以 440 × 264px 为基准，随容器宽度调整；格子保持图标和名称完整，至少高 64px，数量较多时增高并允许创建页纵向滚动。预览格子的可读尺寸与真实终端网格不同；创建页滚动不表示活动面板布局区域可以滚动。

待分配格子显示“待分配”，已分配格子显示对应 Agent 图标、名称和弱化序号；序号只用于创建预览，不加入真实面板名称。超额分配时保留已分配 Agent 的预览。创建分配列表按 Codex、Claude Code、pi 排列；预览和实际创建按同一顺序分组展开各类型数量，不按用户点击加号的先后顺序排列。成功创建后的排列及 Agent 对应关系应与预览一致；不因终端可用空间不足禁用创建。

分配合计与选定总数不一致时，“创建并启动”不可用。分配合计达到或超过选定总数时，各 Agent 数量的加号置灰；同一总数下调整分配需先减少某类，再增加另一类。窗口总数可在一至十范围内直接修改，不受已分配数量限制，也不自动改变已有 Agent 分配。例如已分配六个 Agent 时，可直接将总数减到四，保留原分配并提示“多分配了 2 个”；用户调整分配或总数，使两者一致后才能创建。增加总数也保留已有分配，并显示剩余待分配数量。六个窗口、三类 Agent 各两个仅为页面示例，不代表默认值。

首次引导的窗口总数默认三，各 Agent 数量初始为零，不预先分配；页面初始显示“已分配 0 / 3”及“还需分配 3 个”，“创建并启动”不可用。面板总数范围为一至十；创建后允许关闭全部面板，形成零面板项目。三个面板优先上大下二，允许按空间回退为纵向三格等平铺；其他数量沿用自动布局。首版不继续追求初始排列的优化，用户按需手动调整。实际终端按可用区域呈现，空间不足交由用户处理；原型旧阈值下的窄窗口记录不作为真实 CLI 可用性的验收。

再次进入已有项目使用保存的面板和布局，不重复要求完成创建引导。创建引导中的批量配置与工作区中的按需新增使用相同的 Agent 类型、统一设置与布局规则。

项目名为空或目录无效时不可创建，并对无效目录明确提示。正式应用需检查实际本地目录，原型中的绝对路径格式检查不替代该验证。已添加目录提供“打开已有项目”，不重复创建。启动 Agent 时，若命令或目录等问题导致无法启动，只提示“Agent 无法启动”。不静默替换目录或 Agent 类型。配置期间不启动后台 Agent，取消配置不留下项目或运行实例。

### 4. 动态面板与自动排布

- 用户点击固定显示在工作区右上角的“＋”入口，打开位于主窗口中央的“添加 Agent”大弹窗。弹窗采用 B 的纵向列表，通过左侧图标与名称辨认三种 Agent，背景仍可看到当前项目。点击选项后，在面板数量允许时为当前项目新增并启动一个面板；成功后关闭弹窗，并为当前面板集合自动安排空间。
- 新面板的插入位置和所需空间由程序自动选择：优先局部分割一个现有面板，其他区域保持不动；局部分割不合用时，允许直接重新平铺全部面板。用户无需预先选中某个面板，也不默认从当前选中的面板分出空间；尺寸参考可用于简单排布选择，不作为新增的硬性门槛。
- 用户点击关闭图标时无需确认：结束对应运行实例及其需要清理的子进程，移除面板，按原有分割关系让相邻区域扩展并填满空缺，其他区域保持不动；不因关闭而整体重置布局。
- 应用正常运行期间，已启动的 Agent CLI 进程结束（包括用户在 CLI 内退出或进程异常退出）时，直接关闭对应面板，不保留退出前画面、已退出占位或重新启动入口，也不自动重启。移除其保存的面板配置，并按相同规则调整剩余布局；最后一个面板结束后保留零面板项目。
- 每个项目最多十个面板。面板覆盖可用布局区域，除边框、圆角、分隔线和必要界面间距外，填满布局区域；布局不通过滚动容纳额外面板。
- 支持拖动面板之间的分隔线连续调整大小比例，相邻区域随之增减，始终保持整齐平铺、不重叠，除边框、圆角及必要界面间距外不留下未占用区域。例如三面板上大下小布局中，横向分隔线调整上下区域的高度，下面的竖向分隔线调整下方两个面板的宽度。不提供独立拖动单个面板任意四边的自由缩放方式。
- 三种 Agent 的有效终端以 60 列 × 12 行作为可读性参考；标题栏、边框及终端内边距不计入网格，实际网格随字符尺寸和可用区域换算并传给终端。该值不作为创建、新增、分隔线拖动或主窗口缩小的强制下限；原型旧的 240 × 160px 也不是产品下限。
- 空间不足由用户主动调整主窗口或面板大小。创建、新增、应用重开恢复、项目切换及可用屏幕变化均沿用正常布局与运行流程，不增加空间预检、专门提示、拒绝启动或等待扩容状态；不为此设计隐藏、删除面板或滚动布局方案。每项目最多十个面板是数量上限，不保证任意窗口尺寸下均可舒适使用。
- 用户可从面板顶部拖动到另一个面板上交换位置。鼠标靠近面板上方即可使用顶部拖动区域，不要求移动到右上角的独立小手柄；顶部按钮各自响应点击，终端正文仍用于原生交互与文字选择。
- 用户调整排列和比例后，由程序自动保存，无需点击保存按钮。调整完成后切换项目或退出再重开，应保留最新布局；面板数量未变时，不因重新显示项目而重新自动排布。
- 日常以 2–4 个面板、临时放大与还原为主要使用方式。自动排布以够用、可预测和实现简单为目标，采用局部分割、按原分割关系合并、局部放不下时整体重新平铺的规则。手调结果保存为当前比例，不另设“主力面板”身份或保护优先级，不要求记录手调历史、搜索最少改动方案或逐层挪借空间。局部分割可能改变被选中面板的手调大小，整体重新平铺可改变全部位置和比例；保留手调安排是尽力而为，不是硬性保证。具体分割目标、方向和整体平铺形状采用简单、确定的实现规则即可，不以排列美观或精确保留比例作为验收门槛。
- 调整布局只改变视图及终端尺寸，保留面板中的 CLI 不应因此被重启或终止。
- 主窗口尺寸变化按当前布局的相对比例调整，保留面板排列；不根据终端网格下限限制用户缩小，也不为此重新排列面板或改变布局比例。临时放大只改变查看方式，不覆盖保存的布局。
- 应用重开、切换项目或可用屏幕变化时，在当前可用区域按保存的排列和比例呈现面板，不为容纳布局自动扩大主窗口。重开时启动上次查看项目的 CLI，其他项目在首次切换到时启动；已运行实例继续运行，不因空间不足跳过、延迟、重启或终止实例。
- 单个终端可以滚动查看自身输出。临时放大与还原是日常聚焦当前任务的主要操作，不要求用户频繁拖动分隔线来获得可用空间；还原返回分屏布局，不以放大后的尺寸改写保存的比例。
- 允许关闭最后一个面板，无需确认，停止其运行实例并保留项目。零面板时工作区显示“＋ 添加 Agent”入口；切换项目或重开应用后仍保持空状态，不自动补建面板或启动 Agent。该入口打开同一个“添加 Agent”弹窗，供用户选择 Agent 并新增面板、启动实例。

| 操作 | 面板与布局结果 | 运行结果 |
|---|---|---|
| 引导确认 | 建立整组初始面板与布局 | 启动已分配的 Agent |
| “＋”新增 | 优先局部分割；局部不合用时允许整体重新平铺并改变手调比例；空间不足由用户主动调整大小 | 新增时启动所选 Agent，不以空间是否充足为条件 |
| 关闭面板 | 移除该面板，按原分割关系让相邻区域填满空缺，其他区域保持不动 | 停止被关闭面板的运行实例 |
| 关闭最后一个面板 | 保留项目，保存零面板状态，显示“＋ 添加 Agent”入口 | 停止最后一个运行实例；重开或切回项目不自动启动 Agent |
| 调整大小或交换位置 | 修改当前布局并自动保存 | 现有运行实例继续执行 |
| 临时放大／还原 | 改变查看方式 | 全部运行实例继续执行 |

### 5. CLI 接入与手动恢复

接入 Codex CLI、Claude Code 和 pi 三种 Agent，适用相同的接入要求与验收标准。工作台在项目目录的交互终端中直接执行相应启动命令：Codex 使用 `codex`，Claude Code 使用 `claude`，pi 使用 `pi`。启动体验与用户在本机终端中输入相应命令一致，应使用本机已有的命令环境，正常使用无需先填写可执行文件路径。所有 Agent 的设置集中在同一个设置界面，并供各项目使用。工作台使用本机已安装、登录和配置好的 CLI，不承担安装、升级或账户登录。

CLI 接入要求：

面板继续绑定所选 Agent，由工作台解析程序路径、参数、项目目录和环境变量，通过 PTY 直接启动，不额外套一层 shell，不模拟逐键输入。正常使用无需用户手填可执行文件路径；不预先支持 shell 别名／函数兼容层。从应用图标启动时的 PATH 与必要环境变量须接入验证，不能以原型从当前终端启动的结果代替。

1. 在指定项目目录的交互终端中执行对应 Agent 的启动命令，使用本机已有的命令环境。
2. 正确承载输入、输出、控制键、复制粘贴、输入法、重绘和尺寸变化。
3. 能区分启动失败与已启动运行实例的退出：启动失败只提示“Agent 无法启动”，提示中不附加重试、设置跳转或其他操作；运行实例退出按关闭面板规则处理。
4. 能结束工作台启动的运行实例及需要清理的子进程。
5. 保持 CLI 原生历史选择和手动恢复功能可用。

历史对话的保存、选择和恢复由 CLI 自身负责。用户在终端中执行相应 CLI 的恢复操作；工作台不提供独立历史列表、恢复按钮或跨 CLI 历史管理，也不自动发送恢复命令。

CLI 内手动恢复失败时，由原生 CLI 呈现其结果，工作台不替用户自动新建对话。工作台启动 Agent 失败时只显示“Agent 无法启动”的提示；已启动的 CLI 进程结束时直接关闭其面板，不保留退出状态画面。

### 6. 运行生命周期与退出

| 触发 | 面板与配置 | 运行实例 |
|---|---|---|
| 切换项目、最小化、临时放大其他面板 | 保留 | 继续运行 |
| 主动关闭面板 | 从项目布局移除，并重新排布 | 停止对应实例及需要清理的子进程 |
| 应用正常运行期间，已启动的 CLI 进程结束 | 自动关闭对应面板，移除其保存配置，调整剩余布局；最后一个面板结束后保留零面板项目 | 清理需要清理的子进程，不自动重启，不提供已退出占位或重新启动入口；不把退出视为业务任务完成 |
| 请求退出后取消 | 全部保留 | 全部继续运行 |
| 请求退出后确认 | 保存项目、面板和布局 | 结束全部项目中的实例及需要清理的子进程后退出 |
| 窗口主进程崩溃 | 保留已持久化的项目、面板和布局 | 尽快清理全部受管实例，不让 Agent 长期留在后台 |
| 下次打开工作台 | 进入上次退出时正在查看的项目，显示其保存的面板配置与布局 | 只自动启动该项目的 CLI，不自动恢复原会话 |
| 本次应用运行中首次切换到其他已有项目 | 显示保存的面板配置与布局 | 自动启动该项目的 CLI；此后切走继续运行，再次切回不重复启动 |

退出确认同时覆盖主窗口红色关闭按钮与应用退出命令。取消退出保持现场；确认后不能只清理当前可见项目。清理卡住的实例需要有界结束机制，避免退出无限等待或遗留 Agent。

退出应用与逐个关闭面板的结果不同：退出时保留面板配置，供重开后恢复布局；主动关闭面板或应用正常运行期间 CLI 进程结束，都会将对应面板从保存的配置中移除。应用确认退出或主进程故障清理所引发的 CLI 结束，不执行逐个移除面板配置的规则，以免清空下次要恢复的布局。

窗口主进程异常退出时，尽快停止全部受管运行实例，不自动重开窗口或重发中断指令，并保留可获得的故障信息。由存活的共用终端管理进程发现主进程失联并清理；终端管理进程异常结束时，由主进程检测并承担必要兜底。先利用这两个现有进程与平台能力，不预先增加第三个监控进程或服务。正常退出先请求结束，已退出则尽早完成，超过限定时间再强制处理，不无条件等待固定 600ms。须验证后代及脱离原进程组的工具清理，并识别进程身份，避免误伤其他终端中的程序；这是待验证设计，不能依赖被强制结束的进程执行退出回调，也不能把终止一个 PID 等同于清理全部后代。普通项目切换、视图重新挂载与单个 CLI 退出不等同于主进程故障。

### 7. 保存与恢复的数据边界

已确认由工作台保存的内容：

- 项目身份、目录及项目导航中的可辨识信息。
- 上次退出时正在查看的项目，用于下次打开工作台时直接进入该项目。
- 统一的 Agent 设置，包括各类型的命令路径、启动参数。
- 各项目的面板集合、面板身份和所选 Agent 类型。
- 面板排列、相对大小等布局配置。
- 应用内快捷键与外观设置。

保存分为两类，两类数据都保存在本机并跨应用重启保留：

| 存储位置 | 职责与已确认示例 |
| --- | --- |
| 可手动编辑的本地配置文件 | 默认布局、主题偏好、快捷键、Agent 启动命令与参数等用户配置；设置界面修改写回同一文件，不混入程序自动维护的项目运行现场 |
| SQLite | 程序自动维护的持久化状态，例如项目身份与目录、面板集合及类型、各项目实际布局与比例、上次查看的项目，供应用重开时恢复 |

默认布局用于没有保存布局时的初始安排；已有项目继续恢复 SQLite 中保存的实际布局，避免修改默认值时丢失已手调的安排。新增、关闭、交换面板及拖动分隔线形成的实际布局保存到 SQLite，不反向改写默认布局。

本地配置文件是用户配置的唯一持久化来源。设置界面修改主题、快捷键或 Agent 启动命令与参数时，写回同一份可手动编辑的配置文件；SQLite 不另存这些设置的覆盖值。主题在设置的外观页以列表选择，首版提供跟随系统、深色、浅色，后续可追加更多主题；不使用二元开关作为主题模型。跟随系统仅在应用启动时解析一次，不把当前解析出的颜色模式当作新的用户选择写回，也不在运行中随系统切色。手改文件与界面修改使用同一组配置字段。

第一版在应用启动时读取本地配置文件；外部手改文件后重启应用生效，不做自动监听或热重载。设置界面修改主题时写回文件，并提示“主题已保存，重启应用后生效”；本次应用的工作台、现有面板与之后新增面板均继续使用启动时的主题，不向 Agent 发送自动同步指令。改回本次启动偏好后取消待重启提示。用户自行选择重启时机，沿用退出工作台的确认和运行实例清理规则，不因保存主题自动重启应用或 Agent。快捷键修改仍即时生效并写回文件。Agent 启动命令与参数的修改用于之后新启动的运行实例，不打断或重启已有实例。默认布局只影响没有保存布局的初始安排。第一版暂缓外部编辑与界面写回的冲突检测、合并及解决流程；使用约定为退出应用后手改配置，再启动生效。运行中同时手改与界面保存，暂不保证双方修改均保留。

启动时读取配置，缺失时采用默认值；损坏、读取或保存失败须明确提示，不能将损坏静默当作缺失或假装保存成功。配置先写完整临时文件再替换目标；应用内保存串行处理，磁盘操作不阻塞界面。布局先更新内存，再保存最终状态，允许合并频繁的中间保存请求。

SQLite 中的面板集合与对应布局应使用事务一致提交。布局在用户调整大小或交换位置后自动保存，退出时无需另行确认是否保存；临时放大不覆盖保存结果。新增、关闭等结构变化及对应自动排布也应自动保存，并与其保存的面板集合保持一致。

“恢复布局”指重建保存的面板与空间安排，不代表恢复进程、对话上下文或正在执行的工具。CLI 原生会话资料由 CLI 维护；应用关闭面板、退出或清理自身数据时，不删除这些资料。

终端输出仅在当前运行中保留滚动缓冲，切换项目不清空正在运行的终端缓冲；重开应用后不载入上次终端输出。CLI 自身保存的历史会话及用户手动恢复后由 CLI 呈现的内容不受此范围限制。

### 8. 原生交互、快捷键与 UI

参考产品的一手资料与演示观察见 [UI 调研](./REFERENCE-UI-RESEARCH.md)。具体行为以本规格为准。

终端正文保留 Agent 原生输出及交互层次，VibeBridge 调整字体、行距、配色等基础呈现以适应大量输入输出。本次不要求导入或同步 iTerm2 外观，也不将 CLI 输出替换为工作台自绘的统一聊天界面。当前真实终端体验已获用户接受，作为首版终端基准；长回答、代码、工具输出、权限确认、输入法及分屏／放大等未逐项记录的场景继续在正式集成中验收，不再作为未决视觉选型。模拟内容与参数不作为真实终端验证证据。

- 视觉与整体布局参考 VibeGuild 和 BridgeMind，风格美观、柔和、简洁，偏好非卡片式 UI，减少无关按钮。第一版沿用当前原型的公共视觉基准，导航采用 A、添加弹窗采用 B；两者独立组合，第一版实现后可按使用体验调整。
- 独立系统栏横贯主窗口，Logo 与 mac 按钮同栏，导航折叠开关对齐侧栏右边缘，设置入口位于最右侧。系统栏下方为左侧项目导航和右侧 Agent 终端分屏。
- 项目导航默认采用 A 的展开列表，显示项目名和面板数；折叠后保留窄栏，显示项目图标或缩写，支持直接切换项目。工作区工具栏为 32px 单行，显示项目名、淡色等宽路径、面板计数和右侧“＋”；路径空间不足时中间省略并保留末级目录，主工作台不显示排布缩略图。
- 面板相邻平铺，圆角 10px、描边 1px，工作区外边距和面板间距均为 8px，终端四周内边距为 13px。系统栏、侧栏、画布同色，标题栏与终端背景沿用面板色。分隔线用于调整大小；焦点描边与 3px 光晕使用 Agent 品牌色：Codex 绿、Claude 橙、pi 紫。非焦点面板通过名称文字层级区分，终端内容保持正常对比度。
- 面板顶部保留 31px 的单行窄栏，左上角常驻显示 Agent 图标与名称，例如 Claude Code、Codex、pi。同一项目中的同类面板显示相同的 Agent 名称，不自动添加编号或任务名称；用户通过面板位置和终端内容辨认任务。右侧放大／还原、更多、关闭按钮常驻显示，未聚焦或未悬停时也可使用，不增加顶部高度或形成第二行；CLI 自身输出保持原样。当前视觉记录见 [UI 原型说明](./ui.prototype/README.md)。
- 放大与还原共用一个图标按钮，按当前状态切换动作；关闭面板无需确认，其他操作使用“⋯”入口。顶部同时作为拖动交换位置的区域，顶部按钮各自响应点击，终端正文仍用于原生输入与文字选择。交换目标显示 10% 强调色覆盖与虚线内描边；松开、取消或窗口失焦后清除反馈。
- 工作区右上角固定显示新增面板的“＋”入口，作用于当前项目，侧栏折叠后仍可直接使用。点击后打开位于主窗口中央的“添加 Agent”大弹窗，采用 B 的纵向列表，以左侧图标和名称呈现三种 Agent，背景仍可看到当前项目；新增面板遵循第 4 节数量上限与布局规则。
- 添加弹窗正常状态下只显示 Agent 图标与类型名称（Codex、Claude Code、pi），保留图标形式的关闭入口。不显示额外标题、说明文案、操作提示、项目名称或目录、面板计数。已采用的 B 列表及保留的对比方案见 [UI 原型说明](./ui.prototype/README.md)。
- 临时放大与还原使用同一个按钮：正常分屏时点击放大，放大后点击还原到原来的分屏布局；期间其他实例继续运行，保存的布局不变。
- 鼠标或快捷键选择面板后，输入只交给该面板的运行实例；布局变化不能使焦点与实际输入目标错位。
- 支持可自定义并保存的应用内快捷键，包括项目切换、面板切换、临时放大／还原等。默认优先使用 Command 组合；设置中可搜索操作与组合键、显示绑定冲突并保留原有效绑定，以及一键恢复全部默认绑定。
- 未被应用快捷键处理的输入继续交给 CLI；快捷键仅在应用前台生效，不注册跨应用全局热键。
- Agent 设置为应用级全局页面，覆盖系统栏下方的内容区；左上角“‹ 返回”恢复原项目、布局和运行实例。命令检查采用次级按钮，结果在输入框下方显示；编辑命令后清除旧结果，正式应用必须实际检查命令可用性。
- 提供传统 IDE 风格的深色（Dark）和浅色（Light）主题，默认跟随系统，也可在设置中选择，重启后统一生效；移除页面上的明暗切换按钮；第一版色板沿用 [UI 原型主题令牌](./ui.prototype/README.md#深浅主题令牌)。界面文字按 13 / 12 / 11px 分层，中文优先系统 PingFang，路径和命令使用等宽字体。悬停与焦点过渡为 140ms，面板增删、交换的布局位移为 200ms；分隔线拖动直接跟随指针，尊重系统“减弱动态效果”。
- Agent 启动失败时只提示“Agent 无法启动”，不附加其他操作入口；已启动的 CLI 进程结束则直接关闭对应面板。不根据 Agent 本轮结束、等待输入或审批发出主动提醒或显示任务状态标记；这些状态也不触发关闭面板。

## Testing Decisions

### 使用规模与验证方法

用户日常预计使用一个项目、二至四个 Agent，全部项目合计的使用峰值不超过十个 Agent。这是性能验证依据；每项目最多十个面板仍是产品边界。

用户目前电脑上有 Codex CLI、Claude Code 和 pi 三种 Agent，日常很少主动缩小主窗口。

优先从用户可见的完整流程验证：创建引导、批量启动、新增与关闭面板、自动排布与手调、项目切换、退出与重开。外部 CLI 边界使用可控交互式测试程序，验证输入目标、后台输出、尺寸变化、故障和子进程清理。不要以内部数据库记录或重复实现排布算法的测试代替可见行为。

先复用 xterm.js 已有缓冲、解析与绘制能力，高效传递输出，不因每段输出重新渲染整个 React 工作台。允许跳过中间画面的绘制，但不能任意丢弃原始输出或控制序列，最终画面、输入与滚动回看须正确。终端显示缓存和输出队列应有界，连续输出交给终端引擎并保持 UI 响应。以日常规模和峰值规模检查输入、分隔线拖动、自动排布及项目切换；再用持续大量输出和反复增删面板检查资源释放。实测出现消息过碎、积压或交互延迟时再增加必要批处理／流量控制，不预建消息队列服务或额外中间件。

Codex CLI、Claude Code 和 pi 均为正式兼容验证对象。验证时记录各 CLI 的版本，确认本机终端中可直接执行的启动命令也能在工作台中启动对应 CLI，并检查交互、输入法、复制粘贴、重绘、尺寸调整，以及用户在 CLI 内选择历史并手动恢复的可用性。

### 验收场景

| 编号 | 场景 | 可观察的通过标准 |
|---|---|---|
| AC-01 | 首次添加项目 | 点击项目导航中的添加项目，在右侧进入统一创建页，保留系统栏与导航，隐藏工作区工具栏，取消原项目高亮并高亮添加项目入口；取消恢复原项目高亮，点击已有项目进入对应工作区，已有运行实例不受影响；在同一页编辑项目名、目录、窗口总数和 Agent 分配；确认整组配置后进入工作区并启动 Agent；再次进入项目不重复引导 |
| AC-02 | 三面板初始布局 | 创建三个面板后自动形成平铺布局，空间允许时优先上方一个大面板、下方两个小面板；允许纵向三格等可行排列，不要求固定形状或额外优化自动排列；用户可通过分隔线和顶部拖动手动调整；空间不足由用户调整大小，旧像素阈值下的窄窗口检查不作为真实 CLI 可用性的通过依据 |
| AC-03 | 引导配置 | 简洁单页总数默认三，各 Agent 初始为零，显示“已分配 0 / 3”且创建按钮不可用；名称和目录可编辑，项目名为空或目录无效时不可创建；先手动选择一至十个窗口，再通过逐行加减控件分配各类 Agent 数量；分配列表、预览及实际创建均按 Codex、Claude Code、pi 顺序分组展开；只读缩略图随总数和分配更新，图标和名称完整，可滚动查看创建表单；显示分配进度及不足或超额数量，分配与总数不一致时创建按钮不可用，分配达到或超过总数时各 Agent 加号置灰；已分配六个时可直接把总数减到四，原分配及预览中的已分配 Agent 保留并提示“多分配了 2 个”；不提供布局编辑或逐格分配；选择六个窗口并分配两个 Claude Code、两个 Codex CLI、两个 pi 后，确认创建六个面板，排列与 Agent 对应关系和预览一致，使用填写的项目名称与目录，不因终端空间不足禁用创建或延迟启动；确认前不启动，取消不留下项目或运行实例，再次打开创建页时保留本次应用内的名称、目录、窗口总数与 Agent 分配草稿，应用重启后不恢复草稿 |
| AC-04 | 大小调整与布局自动保存 | 拖动分隔线可连续调整相邻区域比例，始终保持平铺、无重叠，除边框、圆角及必要界面间距外无未占用区域；拖动主窗口边缘缩小时保留当前排列和比例，60 列 × 12 行仅为可读性参考，不作为分隔线或主窗口缩小的拦截线；终端按实际可用区域更新 cols / rows；调整大小或交换位置后无需点击保存，切换项目、退出后重开均保留最新比例与排列及面板对应关系；临时放大不覆盖保存布局 |
| AC-05 | 关闭面板 | 无需确认，停止其运行实例并移除面板；按原有分割关系让相邻区域填满空缺，其他区域保持不动，不整体重置布局；最后一个面板也可关闭，项目保留并显示“＋ 添加 Agent”，切换项目或重开后仍保持零面板状态，不自动启动 Agent |
| AC-06 | 新增与自动排布 | 工作区右上角固定显示“＋”，侧栏折叠后仍可使用；点击打开位于主窗口中央的 B 纵向列表弹窗，Agent 图标在名称左侧，背景仍可看到当前项目；点击 Agent 选项后，在数量允许时新增并启动一个面板，成功后关闭弹窗；程序自动选择插入位置及空间，不要求先选中面板，也不默认拆分当前选中面板；优先局部分割，局部不合用时允许整体重新平铺，手调比例不要求受特殊保护；空间不足不阻止新增或启动、不触发专门提示，由用户主动调整大小；现有 CLI 不被重启；不超过十个面板 |
| AC-07 | 临时放大 | 同一个按钮在放大与还原动作间切换，还原回到原来的分屏布局；不覆盖保存布局，其他运行实例继续执行 |
| AC-08 | 跨项目后台运行 | 项目切换后原项目继续产生输出，回到项目时仍为原运行实例 |
| AC-09 | 同类 Agent 并行 | 同目录多个相同 Agent 能独立输入和输出，不因排布或切换面板而串输入 |
| AC-10 | Agent 命令启动与统一设置 | Codex CLI、Claude Code 和 pi 的设置集中在应用级全局页面管理，返回后恢复原项目、布局与运行实例；命令检查结果显示在输入框下方，编辑命令后清除旧结果；程序在各项目目录的交互终端中直接执行 `codex`、`claude`、`pi`，使用本机已有命令环境；本机终端已可用的命令无需先填写可执行文件路径即可启动，面板的启动目录分别正确；解析路径与环境后通过 PTY 直接启动，不额外套 shell，不模拟逐键输入；从应用图标启动也能正确接入，第一版不预先兼容 shell 别名／函数 |
| AC-11 | 取消退出 | 主窗口关闭和应用退出均先确认；取消后全部运行实例继续执行 |
| AC-12 | 确认退出 | 保存项目、面板与布局，结束所有项目的受管实例及需要清理的子进程；已结束则尽早完成，超时才强制处理，不无条件等待固定时长，不误伤其他终端进程 |
| AC-13 | 重开工作台 | 直接进入上次退出时正在查看的项目，恢复其保存的面板配置与布局，只自动启动该项目的 CLI；其他项目在本次应用运行中首次切换到时自动启动，此后切走继续运行，再次切回不重复启动；无需逐个点击启动入口，不自动执行原会话恢复 |
| AC-14 | 手动恢复会话 | 用户能使用各 CLI 的原生历史选择或恢复操作；工作台不截获或替代这套交互 |
| AC-15 | 启动失败 | Agent 无法启动时只提示“Agent 无法启动”，不附加重试、设置跳转或其他操作入口；不静默替换 Agent 或目录 |
| AC-16 | 输入与快捷键 | 输入只到达选中面板；快捷键可搜索、修改并保存，冲突时提示对象并保留原有效绑定，恢复默认作用于全部绑定；应用后台不响应全局热键 |
| AC-17 | 终端与布局 | CLI 能正常重绘、复制粘贴、调整尺寸；当前运行中的终端输出可滚动，切换项目不清空其缓冲，面板布局区域不滚动；重开应用不由工作台载入上次终端输出，不提供历史终端记录回看入口；CLI 原生历史与手动恢复不受影响 |
| AC-18 | 面板顶部与简洁界面 | 面板圆角 10px、描边 1px，外边距与间距 8px，终端内边距 13px；焦点使用 Codex 绿、Claude 橙、pi 紫，终端内容保持正常对比度；顶部窄栏只有一行高，左上角常驻显示 Agent 图标与名称，同类面板名称相同，不自动添加编号或任务名称；放大／还原、更多、关闭按钮在未聚焦、未悬停时也常驻可用，不额外增加高度；可从顶部拖动交换位置，按钮独立响应点击，交换目标反馈在结束或取消后清除；拖动不重启 CLI，正文仍可选择文字；减弱动态效果时关闭过渡与布局位移 |
| AC-19 | 导航与主题 | 第一版默认使用 A 的展开导航，显示项目名和面板数，折叠窄栏仍可切项目；导航 A 与添加弹窗 B 独立组合；系统栏横贯窗口，工作区工具栏为 32px 单行，主工作台无排布缩略图；主题采用公共令牌，通过设置列表选择，页面无明暗切换按钮；工作台与终端在启动时统一应用，跟随系统也只在启动时解析 |
| AC-20 | 提醒边界 | 不因本轮结束、等待输入或审批产生应用内主动提醒和 macOS 系统通知 |
| AC-21 | 主进程或终端管理进程故障 | 由存活的另一进程发现失联或异常并执行清理，在有界时间内清理受管实例及需要清理的子进程，含脱离原进程组的工具；不误伤其他终端的程序，不自动重开窗口，保留已持久化配置与可获得的故障信息；先使用现有两个进程，不预先增加监控服务 |
| AC-22 | Agent 进程结束 | 应用正常运行期间，已启动的 CLI 正常或异常退出均直接关闭对应面板、移除其保存配置并调整剩余布局，不保留画面或重新启动入口，不自动重启；最后一个面板结束后显示项目空状态；应用退出或故障清理仍保留面板配置；本轮结束、等待输入和审批不关闭面板 |
| AC-23 | 恢复、切换与屏幕变化 | 应用重开、项目切换或可用屏幕变化时，在当前可用区域按保存的排列和比例呈现全部面板，不为容纳布局自动扩窗；空间不足交由用户主动调整大小，不增加专门提示或处理流程，也不因此隐藏、删除面板；CLI 启动与后台运行遵循既有生命周期规则 |
| AC-24 | 配置分工与生效 | 默认布局、主题偏好、快捷键及 Agent 启动命令与参数保存在同一份可手改配置文件；设置界面写回文件，主题保存后提示重启生效，运行中所有面板保持启动主题，快捷键即时生效；外部手改重启后生效，不自动监听；命令变化只影响之后启动的实例。SQLite 保存项目、面板及实际布局等程序状态，不另存用户设置的覆盖值；修改默认布局不覆盖已有项目的实际布局；缺失配置采用默认值，损坏或读取／保存失败明确提示；配置完整临时写入后替换、应用内串行保存，SQLite 事务保持面板与布局一致；布局先更新内存并允许合并中间保存请求，磁盘操作不阻塞界面；外部手改约定在退出后进行，暂不提供并发编辑冲突处理 |

| AC-25 | 共用运行路径与输出响应 | 开发和打包运行使用同一业务启动、交互、保存与清理路径；debug 只增加诊断，应用运行时不自动编译或修复依赖，诊断版本检查不阻塞窗口显示；日常二至四个及全部项目合计十个 Agent 下检查连续输入、切换、拖动和大量输出，最终终端状态与输入目标正确；允许省略中间绘制，但不任意丢弃原始输出或控制序列，不逐段重渲染整个工作台；按实测需要增加批处理或流量控制，不预建中间件 |

本目录已有用于讨论的 throwaway UI 原型及浏览器验证记录，详见 [UI 原型说明](./ui.prototype/README.md#已检查的原型行为)。运行、目录与命令检查、保存和退出仍为模拟，原型尚未落实导航 A 与弹窗 B 的独立组合，仍保留已退出产品范围的旧空间检查及扩窗消息；该 UI 原型没有真实 Electron／PTY／SQLite 集成或子进程清理验收。另建的[真实终端原型](./terminal.prototype/README.md)用于实现前的体验决策，已接入最小 Electron／PTY 链路并进行冒烟检查，已获用户接受当前终端体验；不包含 SQLite 或完整生命周期验收。上述场景仍是正式产品的验收计划。

## Out of Scope

### 范围外功能

- 第一版不另设普通终端面板，不提供独立普通 shell 的创建入口；现有面板继续绑定 Agent 并由工作台自动启动。
- 第一版暂缓外部手改配置与界面写回的冲突检测、合并及解决流程；退出应用后手改，再启动生效。
- 本地配置文件外部修改的自动监听与热重载；手改文件后重启应用生效。运行中主题热切换、Agent 自动主题同步及历史输出重着色不进入第一版，主题更改重启应用后生效。
- 跨应用重启保存、恢复或回看终端输出记录；当前运行中的终端滚动查看仍支持。
- 已有运行面板的原位 Agent 类型切换；用户可关闭后重新新增其他类型。
- Windows、Linux 支持，以及公开分发、自动更新等发布体系。
- CLI 的自动安装、升级和账户登录管理。
- Agent 任务状态提醒、应用内主动提醒和 macOS 系统通知。
- 跨应用全局快捷键、Agent 桌面应用的嵌入或管理。
- 超过十个面板、自由重叠浮动窗口、独立拖动单个面板任意四边的自由缩放、滚动布局和任意嵌套拆分编辑器。

### 工作台的职责边界

- 空间不足的检测、专门提示、创建／新增拦截、按网格限制缩小、自动扩窗及特殊恢复方案均不进入第一版；用户主动调整大小，程序保留正常布局与终端尺寸更新。
- 不导入、列举或管理外部 CLI 历史；用户在原生 CLI 内使用其历史功能不受此界面边界限制。
- 不管理模型账户、代替 CLI 请求模型服务或重做 CLI 对话界面。
- 不进行 Agent 自动协作、任务分派、统一提示词广播或 Agent 间消息转发。
- 不提供代码编辑器、Git 版本控制、工作副本隔离、合并或文件冲突解决流程。
- 不把终端无输出、本轮结束或进程退出当作业务任务成功。
- 不在确认退出后保留 Agent 后台执行，不恢复已结束进程的内存或工具执行现场。
