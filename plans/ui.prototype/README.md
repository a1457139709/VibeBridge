# VibeBridge UI 原型

**THROWAWAY / 仅用于讨论界面与调试对接。** 依据 [SPEC.md](../SPEC.md) 和 [CONTEXT.md](../CONTEXT.md)，使用 TypeScript、React、Vite 和 xterm.js。所有运行行为均为内存模拟。

**终端方向（2026-10-02）**：面板继续绑定 Agent，由工作台自动启动，采用真实 PTY + xterm.js 保留 CLI 原生界面；关注 VibeBridge 内嵌终端的呈现质量，不要求导入或同步 iTerm2 外观。当前手写输出与统一样式仅为占位，未展示或验证真实 Agent 的完整视觉效果。用户已[接受真实终端体验](https://github.com/a1457139709/VibeBridge/issues/17#issuecomment-5951788329)，原有工作台仍是模拟；另建的[真实终端原型](../terminal.prototype/README.md)已接入 Electron + node-pty，可用 `npm run prototype:terminal` 启动。该接受仅限终端；外部 UI 仍以本原型讨论的有效决议和 SPEC 为准，包括导航 A、添加弹窗 B、应用级独立设置页面及后续修订。真实终端测试窗口的简化外壳、调试栏和设置对话框不能替代这些决定。

**第一版已决基准（2026-10-02）：导航 A＋添加 Agent 弹窗 B；60 列 × 12 行保留为终端可读性参考。** 导航、弹窗与网格定义来源于[界面组合与终端网格决议](https://github.com/a1457139709/VibeBridge/issues/11#issuecomment-5943680621)，标题栏、边框及内边距不计入有效网格。后续用户明确将空间不足交由自己调整大小，取消程序强制下限及兜底要求，见[确定创建、恢复和屏幕空间不足时的用户行为](https://github.com/a1457139709/VibeBridge/issues/13)。SPEC 已同步；原型源码仍用同一个 `variant` 选择导航和弹窗，仍按旧的 240 × 160px 检查空间，尚未按最新范围调整。下方三套方案及旧阈值下的浏览器记录保留作讨论证据。

**采纳边界澄清（2026-10-05）**：整体前端界面已经确定。以 UI 原型为依据，是指补齐导航页面打开方式、Agent 面板排列等已在原型中调整清楚的操作细节与交互逻辑；主体产品与技术决策保持不变。页面排布、图标等剩余细修可在实现完成后完善。历史候选、已被后续决定替换的行为及模拟实现不因这一确认自动成为产品要求。

创建交互已由[确定 UI 优先的规格基准、初始排布与创建草稿](https://github.com/a1457139709/VibeBridge/issues/16)确认：首版沿用现有自动排布，初始形状不作为验收门槛，用户在工作区按需手调；取消创建保留本次应用运行的内存草稿，不跨应用重启保存。SPEC 正文和对应验收条款已同步。

增删面板已由[确定自动排布的插入、关闭合并与保留手调规则](https://github.com/a1457139709/VibeBridge/issues/12)确认采用简化策略：新增优先局部分割，局部不合用时允许整体重新平铺；关闭按原分割关系让相邻区域填满空缺。日常以 2–4 个面板、临时放大／还原为主，手调比例尽力保留，不增加主力面板识别或复杂的空间挪借与比例保护规则。该决议中空间不足拒绝新增的旧条款已被后续范围调整替代。已同步 SPEC，原型算法未在本轮修改或重新验证；下文的候选行为与旧模拟记录不等同于该决议已实现。

**空间不足的当前边界**：创建、新增、重开恢复、项目切换和屏幕变化沿用正常布局与运行流程；用户主动调整主窗口或面板大小，程序不增加空间预检、专门提示、网格缩小限制或自动扩窗。原型中的旧拦截、调试下限与 `window.ensure-size` 是遗留候选行为，不是后续宿主必须实现的要求。

原型最初比较的问题：在独立系统栏下方，哪一种项目导航、终端工作台和添加弹窗结构更适合日常工作？三套方案共用同一份项目、面板、布局和运行实例数据，使用单一路由与 `?variant=` 切换；保留对比不表示第一版尚未选定。已确认设置为应用级页面，三套方案共用；打开时替换系统栏下方的整个内容区，返回后恢复原项目与布局，运行实例继续保留。

## 启动

在项目根目录执行：

```sh
npm run prototype
```

打开 <http://127.0.0.1:4173/prototype/workbench>。首次获取源码后先执行 `npm ci`；当前工作目录已安装依赖。预览服务只监听本机，端口固定为 4173。

## 演示入口

同一路由可以附加 `scene` 参数，直接进入对应界面。例如：

- [创建引导](http://127.0.0.1:4173/prototype/workbench?variant=A&scene=setup&theme=light)
- [添加 Agent](http://127.0.0.1:4173/prototype/workbench?variant=A&scene=add&theme=dark)
- [统一设置](http://127.0.0.1:4173/prototype/workbench?variant=A&scene=settings&theme=dark)
- [零面板项目](http://127.0.0.1:4173/prototype/workbench?variant=A&scene=empty&theme=dark)
- [退出确认](http://127.0.0.1:4173/prototype/workbench?variant=A&scene=quit&theme=dark)
- [状态与对接调试](http://127.0.0.1:4173/prototype/workbench?variant=A&debug=1&theme=dark)

点击左侧“添加项目”直接进入统一创建页，不再先打开目录对话框。项目名、绝对目录、窗口总数和 Agent 分配都在同一页编辑；项目名默认随目录末级名称更新，手动命名后独立保留。引导默认总数为 3，各类型均为 0；总数独立于分配合计，超额时保留原分配并禁止创建。目录无效、项目名为空或分配未完成时无法创建；原型另有尚未移除的空间不足拦截，正式产品已取消这一要求。已添加的目录提供“打开已有项目”，避免重复创建。取消不新增项目或运行实例，草稿保留在当前页面内存中；确认后项目使用填写的名称，Agent 使用填写的目录。

创建页上方显示自动排布缩略图，保留现有排布规则：三面板优先上大下二，可按可用空间回退其他平铺；其他数量仍由原算法生成。首版不要求固定初始形状，排列不合用时进入工作区后手动调整。窗口数量加减实时改变预览矩形，Agent 加减同步更新类型和待分配状态；未分配的面板用实线边框及次要文字色显示“待分配”。超额分配时预览保留已分配的 Agent，直到数量重新一致。分配列表、预览和实际创建均按 Codex、Claude Code、pi 的顺序分组展开各类型数量，不按加号点击顺序排列。缩略图仅用于查看，不增加布局选择或比例拖拽。输入目录只是原型占位，不验证该目录在磁盘上是否存在。`scene=setup` 和此前的 `scene=directory` 均进入统一创建页。

创建页内容宽度为 440 px，顶部留 8vh 空白，允许纵向滚动。页面标题独立放在最上方，使用 22 px / 600，说明为 13 px；分段标题 13 px / 600、输入标签 12 px / 500，辅助文字 12 px，均使用共用文字令牌。标题下方先放项目名称与目录，组成项目信息组；分割线之后依次是缩略图、窗口数量和 Agent 分配，组成窗口配置组。两组均为 440 px 宽，中间分割线高 1 px、上下各留 24 px，不在窗口配置组内部添加分组分割线。预览与表单同宽，以 440 × 264 px、5:3 为基准；按容器实际尺寸计算内部矩形，每格至少高 64 px，窄窗口或数量较多时自动增加预览高度，通过页面纵向滚动完整展示；外层使用面板色、圆角 12 px、1 px 低对比实线边框、10 px 内边距，内部面板圆角及间隙均为 8 px。下方左对齐显示 12 px 的“自动排布 · N 个面板”，继续复用实际布局树和分割比例。

未分配格子显示居中的 20 px 虚线圆及 12 px 次要文字色“待分配”；已分配格子显示 24 px Agent 图标与名称，边框使用对应品牌色 40% 透明度，背景混入 6% 品牌色。右上角序号使用 11 px 弱化文字色；数量较多时仍显示名称和序号。边框与底色过渡、图标及名称淡入为 150 ms，切换 Agent 会重新淡入；系统或调试开关启用减弱动态效果时关闭这些动效。

标签到输入框间距 8 px，输入到辅助文字 6 px，分组之间 24 px。数量行统一为 56 px；输入框和底部按钮为 36 px，步进器为 32 px，控件圆角为 8 px。分配行 Agent 图标 20 px，使用与面板标题相同的实际线宽；名称 13 px / 500。“取消”文字左缘与表单对齐。创建页保留系统栏与项目导航，右侧隐藏工作区工具栏；点击已有项目可直接进入对应工作区，创建草稿仍保留。创建页打开时侧栏项目取消高亮，项目导航的“添加项目”入口显示选中底色（不是工作区“添加 Agent”的“＋”）；返回后恢复原项目高亮。

分配进度按窗口总数生成分段，每段高 4 px、间隙 4 px。已分配段使用强调色，未分配段为中性浅底；超额时整条改为琥珀色，保留原分配并禁止创建。状态说明用次要文字色，数字用正文色。主按钮禁用时仅将底色透明度降至 40%，文字保持正常对比度；可用时使用实心强调底色，深色主题用深字、浅色用白字，悬停略提亮，箭头与文字间距 6 px。

终端模拟支持 `pwd`、`/help`、`/clear`、`/exit`、普通文字输入、Ctrl+C 和终端文字选择。普通输入会收到明确的模拟回复；`/exit` 会移除面板，最后一个退出后进入项目空状态。

现有原型候选行为：通过顶部区域拖动到其他面板，可以交换位置。分隔线连续调整相邻区域的比例，关闭面板会合并对应空间。新增会先尝试拆分可容纳新面板的区域；必要时扩大重排范围，仍无法满足最小尺寸则保留原布局并拒绝启动，这一拦截是尚未移除的旧行为。临时放大保留原布局和其他运行实例。正式产品采用文首已决的简化规则，不要求照搬候选算法的逐步调整策略或空间不足拦截。

交换拖拽时，源面板透明度降至 70%，目标面板覆盖 10% 统一强调色填充和距边缘 4 px 的虚线内描边。松开、Esc 取消、窗口失焦或源面板卸载后均清除临时反馈。

全局设置的快捷键页支持搜索操作名、组合键、⌘ 等符号及 Cmd / Command / Ctrl / Option 名称。点击输入框后按新的组合键；重复绑定和固定的 ⌘1–9 会显示冲突对象，原绑定保持不变。Esc 取消当前编辑；“恢复默认”一次恢复全部四项可编辑绑定，即使当前搜索隐藏了部分操作。

设置页的“‹ 返回”位于左上角标题区域，采用幽灵按钮样式。Agent 命令检查采用带图标的小号次级按钮，悬停有底色；检查结果在输入框下方用勾 / 叉和一行淡字显示。修改启动命令后清除旧结果，检查仍为内存模拟。

三套方案共用界面基准：面板圆角 10 px、描边 1 px，工作区外边距和分隔间距 8 px，终端四周内边距 13 px，并由面板圆角裁切。焦点描边与 3 px 光晕沿用各 Agent 的品牌色：Codex 绿、Claude 橙、pi 紫；两个主题按同一色相调整亮度。标题栏底色不变，仅名称文字加深；右上角放大、更多、关闭按钮常驻显示。非焦点面板通过名称文字层级区分，终端内容不再整体降低透明度。文字分为 13 / 12 / 11 px，中文优先使用系统 PingFang，路径和命令使用等宽字体；界面小标签统一中文并取消英文大写加字距。

悬停和焦点过渡为 140 ms。增删及交换面板时，矩形位置与尺寸使用 200 ms 缓动；面板按 ID 保留同一个终端视图。拖动分隔线直接跟随指针。系统开启“减弱动态效果”时关闭过渡与位移，并监听系统偏好变化。

```js
const prototype = window.__VIBEBRIDGE_PROTOTYPE__;

// 观察命令；不执行任何真实操作。
const unsubscribe = prototype.subscribeCommands(command => console.log(command));

prototype.getSnapshot();  // 保存边界：没有 runId、进程状态或终端输出
```

按[技术选型复核](https://github.com/a1457139709/VibeBridge/issues/14)的用户确认，正式接入采用 Electron、xterm.js、node-pty 和一个共用独立终端管理进程。默认布局、主题偏好、快捷键及 Agent 启动命令与参数放在可手改的本地配置文件，设置界面写回同一文件，主题重启后生效、快捷键即时生效，SQLite 不另存这些设置的覆盖值。外部手改文件重启应用后生效，不做自动监听；Agent 命令的修改只影响之后启动的实例，不打断已有实例。程序维护的项目、面板和实际布局等重启恢复状态放在 SQLite，基础保存已确定为配置完整临时写入后替换、应用内串行保存及 SQLite 事务；缺失采用默认值，损坏或读写失败明确提示。外部编辑冲突检测与合并首版暂缓，约定退出应用后手改。需处理异步启动及清理确认，不接入已退出范围的 `window.ensure-size`。真实 PTY 必须收到 xterm 原始输入，包括控制键和转义序列；当前模拟 prompt 只处理基本行输入。原型代码不能直接视为 CLI 兼容、文件与 SQLite 持久化或子进程清理实现。

按[确定第一版是否另设普通终端面板](https://github.com/a1457139709/VibeBridge/issues/18)的用户确认，第一版不增加普通终端面板或独立 shell 创建入口；面板继续绑定 Agent，由工作台自动启动。

## 边界与后续决策

刷新页面会重置所有数据。模拟退出和重开只验证同一页面内的生命周期语义，不构成跨应用重启持久化。没有访问本地目录、启动真实 CLI、接入 SQLite 或执行系统退出与子进程清理；CLI 原生历史、输入法及 PTY 兼容性仍需在 Electron 接入后验收。

原型提供的尺寸约束计算和 `window.ensure-size` 消息仍为旧候选实现；按最新用户范围，宿主无需实现按终端网格限制缩小或自动扩窗。正常终端尺寸更新继续保留，当前布局插入算法也只是用于讨论的候选实现。

**当前结论：系统栏、全局设置以及面板、字体、动效基准已按反馈统一；深浅主题共用令牌，面板焦点沿用 Agent 品牌色，右上角操作按钮常驻显示，终端与面板同色；项目创建合并为一个页面，支持项目名、目录和 Agent 配置，并在引导中实时预览自动排布。第一版已选导航 A 与添加弹窗 B，A / B / C 继续保留供对比。** 已确认的界面条款及空间不足由用户处理的范围已同步 SPEC，决策及后续问题已纳入[第一版决策地图](https://github.com/a1457139709/VibeBridge/issues/1)。本轮规格对齐不修改 CONTEXT.md；原型源码及既有本地修改继续保留用于联调，尚未落实界面组合或移除旧空间拦截。进入正式实现时，再按照 prototype 技能将完整原型归档到独立临时分支，记录选择理由，并重新实现被采纳的界面。
