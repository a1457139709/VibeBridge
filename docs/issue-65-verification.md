# Issue 65：设置提交与迁移冲突提醒

实施依据：[2026-10-16 已确认决议](https://github.com/a1457139709/VibeBridge/issues/65#issuecomment-6216534444)。基线为 `0a90af32f806aae86b34f7cdc1833df5633cf8d8`，当前分支 `main`。环境：macOS，Electron 44.5.1。

## 提交边界

`Workbench.saveSettings(patch)` 保留现有 Electron 传输和主进程操作队列，返回可跨 IPC 传递的 `SettingsSaveResult`：成功包含完整已保存配置；校验失败包含全部字段问题；存储或传输不可用返回明确的失败类别和反馈文案。

`SettingsFile.commit(current, patch)` 将本次修改与主进程当前配置合并，校验完整配置，执行一次完整文件写入与替换。写入成功后 Workbench 才发布新配置。普通保存仅选择当前分类；“保存并返回”一次提交所有有改动分类。任一校验或写盘失败都不更新有效值，页面保留全部草稿，也不执行原导航动作。

页面不再逐分类保存、优先保存快捷键，或根据 Electron 异常前缀和中文文案判断问题分类。`settingsCategories` 是导航名称、顺序、字段归属与校验的共同定义；草稿比较、patch 选择、问题收集与首次定位均遍历此定义。调整顺序不需修改这些流程；新增分类需要声明其字段、校验和具体页面内容，无需增加保存协调分支或通用表单生成器。

即时字段提示与提交校验使用同一规则。页面根据结构化字段标识定位实际控件，在分类切换和解除禁用完成后聚焦。恢复默认、放弃更改和各分类草稿仍由页面管理；保存成功更新基线，未提交分类的草稿保持原样。

**职责检查：** 删除上述提交和分类规则后，页面就必须重新掌握字段选择、跨分类保存顺序、完整配置校验与错误识别；本次改动实际删除了这些调用者职责，并非增加单纯转发层。当前配置仍归 Workbench 管理，文件迁移及损坏保护仍归 SettingsFile 管理。

## 启动与生效规则

缺失动作迁移产生的快捷键冲突通过快照单独标记。应用显示可关闭提醒，并提供直接进入快捷键分类的入口；关闭仅影响本次启动。未修复重开再次提醒，修复保存后清除标记，重开不再出现。未修复退出继续保留原文件；损坏配置仍拒绝覆盖。

手动保存、命令显式检查、Agent 设置只影响后续运行实例、主题重启生效、现有布局及快捷键生效边界保持不变。保存期间继续禁止编辑、重复提交和离开。
