预览是独立的冻结 DOM/Canvas 绘制副本，不调用布局保存或终端尺寸修改。命中判断使用拖动开始时的原区域，松手时重新检查实际坐标，只有有效目标才提交。真实面板、输入焦点、终端文字选区在悬停时保持。Escape、原生窗口失焦、区域变化或结束均移除副本和监听。

## 已覆盖的桌面行为

- 实测字符单元约 **7.824 × 17.000 CSS px**。普通与嵌套布局的宽、高下限分别保留两列或两行内容加细边框；所有受影响面板均未越界。正常标题、按钮、内边距不占极小内容空间；拉大恢复标题，原 `.xterm` 节点仍为同一个，CLI 仍回报输入。
- 主窗口缩小不改写比例。宽、高分别覆盖单侧不足时不能继续缩小但能增大、另一侧保持下限、两侧都不足无法移动；不足窗口仍能新增并启动面板。合入 #46 后，导航在窄窗口主动让出空间，宽度两侧不足用例改用小嵌套区域制造真实不足，不假设导航固定占宽。恢复窗口后旧运行 ID 不变。
- 原生拖动 A，依次悬停 B、C，再重复悬停 C；检查预览图像位于对应原区域、B 归位、真实面板区域未移动。跟随影像包含当前 CLI 可见文字，透明度为 0.5，未增加滤镜模糊。
- 悬停中向可控 CLI 查询真实行列，前后尺寸一致；原生键盘输入只进入拖动前的选中面板，原生复制证明既有终端文字选区保持；延迟后台输出继续到达，运行 ID 与保存布局不变。
- 回来源、移出目标、无效松手、未收到最后一次 move 而直接在无效坐标松手、Escape、真实窗口 blur 均不交换，清理影像。有效松手后才改变实际终端尺寸和保存布局，原选中面板身份保持。
- 切换项目返回保留终端节点、运行 ID 及已提交布局；真正退出并重开 Electron 恢复布局，运行实例为新 ID。测试退出检查受管 PID 已结束。
- 设置暂时隐藏工作区不应被识别为极小面板；返回后恢复原选中终端的输入焦点。

## 红绿循环与限制

先复现没有整面板预览的失败，再实现影像与提交；同次拖动中先增大后反向的用例复现了退回不足尺寸的问题，修复为增长时推进允许边界；扩展 native mouseup 用例复现“沿用旧悬停目标而误提交”，修复为松手坐标重新命中。完整桌面回归还发现隐藏工作区的 ResizeObserver 会误切极小模式并阻止焦点恢复；修复为忽略没有布局盒的隐藏面板。测试驱动验证用户可观察结果，未用静态核查替代体验测试。

减弱动态效果的 CSS 规则继续关闭过渡和动画，交换结果副本仍显示。**本次没有修改 macOS 用户的减弱动态效果设置；实际手感与该系统设置下的体验仍待用户人工确认。** 自动化截图及 DOM/CLI 证据不能代替此项确认。
