# #28 退出、故障清理与完整流程验收

日期：2026-10-08。依据 [#28](https://github.com/a1457139709/VibeBridge/issues/28) 和父规格 [#19](https://github.com/a1457139709/VibeBridge/issues/19)。前置 #24–#27 已关闭。沿用已确认的 Workbench 共用业务入口、正式桌面流程和可控交互 CLI 边界；没有读取或复用原型代码、设计或生命周期规则。

## 实现与聚焦验证

- 原有定时父子关系采样会漏掉短命父进程退出后的脱离进程组后代。先扩展既有终端故障测试，复现残留，再加入每次运行的随机归属标记。macOS 进程检查仅保留该标记与 PID／启动时间，不记录环境或命令行；主进程即使没收到最后一次进程采样，也能清理该次工作台的受管运行。
- 主进程 SIGKILL：使用真实 Workbench 的独立测试主进程启动两个项目及双层 fork 后代，由终端管理进程检测 IPC 断开并清理。实测约 0.1 秒；相同程序的无关进程存活，已保存的项目、面板、布局及上次项目可重开读取。测试主进程被强杀，没有依赖其退出回调。
- 终端管理进程 SIGKILL：扩展既有测试覆盖两个项目及脱离进程组后代；清理后面板配置保留、输入失败、运行状态不再显示为运行中，终端视图资源随状态释放。最近故障的信号／退出原因写入 `last-failure.json`；主进程故障记录连接断开及可获得的清理错误。
- 正常退出复用已有保存恢复测试，增加“布局保存尚未返回即退出”的检查；协作进程退出不等待两秒强制期限。单独检查拒绝 SIGTERM 的可控进程：先收到结束请求，约 2.1 秒后才被强制结束；同时覆盖输出因消费暂停时的退出清理。该检查实际暴露 macOS 暂停读取会阻碍被强杀进程的 PTY 退出，现仅在 SIGKILL 后恢复读取并转发有限的内核残留，不放开仍在运行的输出生产者。
- 桌面流程保留创建、输入目标、布局交换与分隔线、视图重挂载、设置、跨项目恢复等既有检查，补充窗口关闭和应用退出分别取消后所有运行身份不变。确认退出结束所有项目，重开恢复配置且创建新运行；普通 CLI 退出仍由原测试验证删除面板。
- 清理使用原有两个进程，没有第三个监控服务、自动重开窗口、会话恢复框架或运行时依赖修复。

## 持续输出与资源

复用同一个可控交互程序，在现有桌面流程中检查四个及跨项目合计十个运行；此前流程已覆盖日常二至三个运行。每个程序产生约 8.3 MB 带颜色及光标控制的输出；输入、项目切换和原生分隔线拖动与输出同时进行。终端最后执行清屏、输出 PID、查询光标，要求所有可见及后台 xterm 都返回最终的第 2 行第 1 列，再检查运行身份未变。额外面板关闭后检查其进程消失；最终退出继续检查所有运行释放。不是截图或视觉流畅度验收。

| 开发构建实测 | 四个运行 | 十个运行 |
|---|---:|---:|
| 流量控制前输入回显 | 48 ms | 158 ms |
| 流量控制前两次项目切换 | 337 ms | 682 ms |
| 流量控制后输入回显 | 37 ms | 47 ms |
| 流量控制后两次项目切换 | 100 ms | 119 ms |
| 流量控制后全部终端解析完成 | 600 ms | 1385 ms |

这些是本机一次聚焦负载的观察值，不是持续性能保证。根据已观察到的延迟加入 xterm 解析确认和 PTY 暂停／恢复，未增加输出丢弃、整页重渲染或额外批处理框架。每运行未确认字符串约 128 Ki code units 加一个已读取块，低于 64 Ki 后恢复；xterm 滚动缓冲 5000 行。关闭或退出期间继续接受解析确认且保留输出上限；即使消费者不再确认，终止信号仍能送达，超时强制清理仍有效。测试观察器自身只保留每运行末尾 2048 字符和计数。

最终本地打包文件的同一检查亦通过：四／十个运行的输入分别 39／43 ms，两次切换 63／137 ms，全部解析完成 622／1391 ms。Electron 各进程合计 working set 在四个运行负载前后为 521→672 MiB，十个运行为 672→727 MiB；此值包含终端缓冲、渲染及宿主缓存，不等于产品独占内存或泄漏诊断。附加运行关闭与最终退出后的进程释放断言均通过。

平台依据：[Apple ps 手册](https://github.com/apple-oss-distributions/adv_cmds/blob/main/ps/ps.1)、[Node IPC 断开事件](https://nodejs.org/api/process.html#event-disconnect)、[xterm 流量控制](https://xtermjs.org/docs/guides/flowcontrol/)。采用 macOS 的启动环境读取与可继承归属标记，针对本机同用户受管工具；没有添加跨平台进程监控。
