## 调用者职责与 interface

| 协调知识 | 改造前 | 改造后 |
| --- | --- | --- |
| 每项目选中／临时放大、目标有效性与回退 | App 保存状态，导航与 Workspace 分别判断 | `panel-location` 保存同一份状态并提供有效查看结果 |
| 定位版本、动画对象与取消顺序 | App | module 内部的当前操作与阶段 |
| 焦点请求计数、等待帧及旧任务清理 | App 发计数，Workspace 解释并安排帧 | module 连接实际提交界面并聚焦，调用者不再传计数 |
| 导航、快捷键、直接面板交互 | 分别组合状态与聚焦 | 两个配套 hook 共用规则，保留直接操作的即时焦点 |
| 最新会话标题与定位结果提示 | App 的额外运行快照引用 | module 使用最新宿主快照 |
| 设置离开许可、页面与工作台快照 | App | 仍由 App 提供；许可通过后才提交定位 |
| 布局保存、交换预览、终端实例及输入输出 | 既有实现 | 仍由既有实现负责 |

根 hook `usePanelLocation` 接收快照、可见性，以及激活项目、显示工作台、报告提示三项宿主能力。App 只提交 `openProject`、`locatePanel`、`leaveWorkbench` 意图，读取 `view` 与 `locating` 输出。

Workspace 使用 `useWorkspacePanelLocation`，提供同一管理入口、当前项目、布局区域 ref 和空间排列顺序；使用返回的查看状态、选择／标题栏聚焦／焦点反馈、放大还原、前后面板与新增成功入口。hook 内部在布局提交后连接 DOM，卸载时断开自己的连接。内部协调器通过 module 私有 Symbol 共享，不导出为第二套测试接口。

**Deletion test：通过。** 删除 module 后，App 和 Workspace 就需要重新掌握每项目查看状态、有效性修正、操作失效、两段动画、DOM 提交与终端输入就绪的区别、焦点反馈抑制、聚焦重试及清理。这些职责已从调用者的实际差异中删除，收益并非仅移动原 `switchPanel` 函数。

## 执行规则

- 有效的新操作同步替代旧定位；无效目标不替代有效的待完成操作。失效操作的迟到回执、动画与失败回调不能继续聚焦或报告成功。
- 已提交的项目激活仍可能改变主进程快照。module 只允许当前被接受的项目驱动聚焦，不把前端取消解释为撤销后端操作。
- 激活回执、匹配查看状态的实际 Workspace 提交、运行终端真正获得原生焦点分别判断。正常更换 Workspace 不取消根级定位；根卸载、隐藏或离开工作台会清理。
- 目标消失时终止原定位并修正查看状态，回退面板不作为原目标报告成功。
- 程序聚焦产生的同步焦点事件在 module 内识别。标题栏和放大操作对已挂载终端保留即时聚焦，内容选择保留原有选择行为。
- 没有运行实例的目标可以完成显示，但会释放旧终端焦点；实例后来进入 running 时再尝试实际聚焦。`focusTerminal` 返回实际焦点检查结果。
- 临时查看状态不写入保存布局；分屏／放大继承、项目标题导航的查看状态记忆、减弱动态效果与动画不可用时的最新标题提示保持原规则。
