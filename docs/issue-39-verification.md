## 复现与根因

`npm run test:desktop -- --setup` 的最小复现是在真实创建页聚焦并离开空名称框，断言显示「请输入项目名称」。修复前连续两次失败。扩展后的同一入口还捕获了清空后选择目录不填名、手输路径误改名称、选择返回时覆盖较新输入、缺少控制字符提示、重复目录缺少红色原因，以及侧栏 emoji 被截断。

- 空名称只参与按钮禁用，没有字段提示；空目录被非空判断排除。非空无效目录原本已有红字，本轮增强其字段呈现，没有将它误记为新修复的缺失校验。
- 名称联动依赖历史 `named` 标记，而目录选择回调使用打开时的草稿。现改为仅在选择完成时，通过当前草稿判断名称是否为空；手输目录不改名。
- 名称只有空白校验，缺少控制字符约束。现由共享规则处理自动名称，并在界面和主进程拒绝不合法手填名称；粘贴检查发生在浏览器可能丢弃换行之前。
- 重复目录只有次要链接，现展示红色原因及已有项目名，并提供独立按钮。名称缩写按完整字素提取，保留组合 emoji。

## PR #40：名称错误提示行的空白占位修复

2026-10-10，基于 `0a1c9fc88ac20db3cc0c8e796824ad1cab6d876d` 处理[评审反馈](https://github.com/a1457139709/VibeBridge/pull/40#issuecomment-6097953689)。以下是本次补充验证，前文仍保留其原适用版本。

- **复现：** 先补充实际页面几何断言，再运行 `npm run test:desktop -- --setup`。修复前连续两次在初始空名称处失败：提示行高度实际为 22px，预期为 0；第二次复现已移除目录创建等无关准备步骤。
- **根因：** 名称提示文字为空时，容器仍参与布局，`.field-status` 的最小高度与内边距保留了占位。实测名称框到下一字段标签的间距为 38px；仅隐藏提示容器后恢复为正常的 16px。仅移除下一标签的间距仍留下 22px，且纠正名称后错误文字与无效标记均已清空，排除标签间距和校验状态残留。
- **修复：** 名称提示行在没有错误信息时隐藏，有错误时显示。保留原有名称校验及目录提示行为。
- **回归：** 在真实创建页面检查初始收起、失焦报错展开、修正后收起、再次清空后重新展开，以及纠正粘贴控制字符后收起；同时断言提示行高度和字段间距，避免只验证文字消失。
- **结果：** `npm run test:desktop -- --setup` 通过，包括原有目录选择、自动填名、特殊字符、真实创建与重复目录打开检查；`npm run build`（含类型检查）、`npm test`（14/14）、测试脚本语法检查及 `git diff --check` 通过。桌面与业务测试在允许 Electron/进程查询的环境运行；Vite 大 chunk 提示和桌面 Shared Dictionary cache 警告仍存在，未影响断言或退出结果。
