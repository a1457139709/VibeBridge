# 运行实例和终端只相信宿主确认过的事实

运行实例管理（`app/main/runs/`）、终端宿主（`app/terminal/`）、派发（`app/main/dispatch.ts`）和渲染进程的终端（`app/renderer/panels/terminals.ts`）之间的事件可能乱序、迟到或丢失。下面这些决定让它们在这种情况下仍然一致。

## 启动与结束（`run-supervision.ts`、`project-panels.ts`、`model.ts`）

- 没有收到宿主的回应，不能证明进程没有启动。启动结果分为确认、失败和未确认；未确认的启动可能仍在运行，已观察到的运行实例保留，继续接受它之后的事件，不隐式重试。只有失败的启动才确定没有启动。宿主自己失败时，它已经停掉了它运行的一切，不会再报告什么。
- 请求清理之前先做标记：退出事件可能比回应先到。
- 不由工作台停止而结束的运行，包括 Agent 正常结束（例如在 CLI 里 `/exit`），既不表示故障，也不表示任务失败；报告时它已经离开运行列表。
- 项目设置撤销 Agent 从未启动的面板；恢复的布局保留启动失败的面板。这既不是关闭面板，也不是运行退出。
- 托盘面板一直在它启动时的目录里运行；项目目录改变时只重启常驻面板。
- 托盘面板变常驻时，用渲染进程为这次放置算好的目标布局；交换时被替换的常驻面板进入托盘末尾。运行实例不受影响。
- `project-panels.ts` 只改面板；找项目和串行化工作是调用方的事。

## 会话标题（`run-supervision.ts`、`session-title.ts`）

- Agent 忙碌时在终端标题里转一个 spinner，只有新的会话标题才算变化。
- Codex 0.162.1 会轮流使用全部十个 Unicode 标题 spinner 帧，解析时都要去掉。
- 空字段和重叠的分隔符保留为未知格式，不猜测。

## 终端宿主（`app/terminal/host.ts`、`titles.ts`）

- 对端可能在检查连接之后、写入之前断开；清理交给断开事件。
- macOS 在回收被杀掉的生产者时可能等 PTY 输出排空。SIGKILL 之后只剩有限的内核缓冲区，直接转发，不等已经失联的渲染进程。
- 流控额度覆盖经由 IPC 和 xterm 解析器的每一跳；输出从不截断。解析器的确认不排在停止或启动操作后面。
- 布局过渡可能在面板停止之后才结束，只有输入需要活着的目标。正在停止的运行在清理结束前仍显示面板，期间丢弃键入和终端应答。
- 标题只从 OSC 标题信号里观察，调用方照常转发原始 PTY 数据。遇到另一个转义序列时放弃未完成的 OSC，开始下一个序列。

## 派发（`app/main/dispatch.ts`）

- 派发不检查目标在做什么，也不检查 skill 是否已安装。
- 文本用 bracketed paste 送入，CLI 把它当作输入框里键入的内容，不对其中的换行起反应。
- 派发到新面板：提交时把指令作为启动参数交给新面板；填入时新面板不带指令启动，等它第一次报告就绪后粘贴。请求新面板时就算已发送。
- 派发到已有运行的面板：粘贴到输入框已有内容之后，再按 Enter 提交；写完才算已发送。写入之前先取会话，所以写入期间切换会话，记录留在写入的那个会话上。
- 记录写在文本送入时目标运行所在的会话上，或它报告的第一个会话上（ADR 0003）。

## 渲染进程的终端（`terminals.ts`、`terminal.css`）

- xterm 在屏幕不可见时暂停渲染，只在再次渲染时应用新尺寸，却立即调整滚动区域。按这种不一致夹紧的滚动位置看起来像用户向上滚动，屏幕就不再跟随输出，所以适配尺寸要等屏幕可见。xterm 自己的观察者在同一次通知里恢复渲染，适配放在它之后的那一帧。
- 适配时网格像素和终端行列可能在不同帧更新，二者的商不可靠；行的字体和间距作为一个整体从渲染好的行上量。
- 运行结束前刚发出的输入，会在退出销毁屏幕之后被拒绝；只有活着的屏幕才报告。
- xterm 把 Shift+Enter 发成 Enter 的回车；Agent CLI 把 CSI u 形式读作提示里的换行，所以发 CSI u。
- xterm 按 32 个相同字符的宽度确定每个字形的大小；Chromium 的标点挤压会把一串全角标点压成半宽，单独的标点却按全宽绘制，把后面的文字推出单元格。`terminal.css` 关闭这种挤压。
