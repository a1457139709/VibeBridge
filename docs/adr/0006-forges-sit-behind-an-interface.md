# Forge 藏在接口后面，每个 Forge 一个适配器

仓库绑定、issue 与 pull request 视图、派发都要读写 Forge。工作台只通过一个与具体 Forge 无关的 **Forge 接口**使用它，每个 Forge 一个适配器，放在一张封闭的表里。接入新的 Forge 只新增一个适配器。

- **仓库引用 = Forge ID + 主机 + 仓库 ID + 仓库路径**。前三项确定是哪个仓库，判断两个引用是否同一个仓库只比较这三项：
  - 主机是仓库所在的 Forge 实例。自建实例的仓库 ID 只在本实例内唯一，所以引用要带主机。
  - 仓库 ID 是 Forge 自己给仓库的 ID，改名和转移都不变。
  - 路径是最近一次见到仓库的位置，层级因 Forge 而异，适配器之外不拆分它。
- **按 ID 跟随仓库**：读取直接用绑定路径，并在同一个请求里取回应答仓库的 ID 和当前路径来核对：
  - ID 和路径都一致：直接用结果。
  - ID 一致、路径不同（改名或转移后的重定向）：绑定跟到新路径，按新路径重查一次。
  - 路径查不到，或 ID 不一致：按 ID 定位，找到就跟到新路径并重查，找不到按「无法访问」处理。
  - 写入直接用绑定路径，信任最近一次读取的核对。剩下的风险是两次读取之间恰好改名、旧路径上又恰好出现另一个仓库，可以接受。
  - 理由：改名、转移很少发生，常见情况不该为它们每次多付一个串行往返（实测约 1 秒）。危险的情况（旧路径上换成了另一个仓库）由读取时的核对兜住。
- **领域形状**：接口只返回领域形状，命名与具体 Forge 无关，不暴露 CLI 的输出格式。
- **四类失败**：未安装、未登录、无法访问、暂时性失败，都带上 Forge 返回的原文；怎样呈现和恢复由适配器提供。
- **能力声明**：Forge 之间的功能差异由适配器声明，Forge 没有的能力界面不显示。
- **默认 Forge**：未绑定的项目从默认 Forge 的默认主机列出可绑定的仓库；出现第二个适配器或第二个主机时，再决定用户怎样选择。

## Considered Options

- **直接对接单一 Forge**：接口更简单，但仓库引用、失败类型和命名都会带上那个 Forge 的形状，接第二个时接口和存储格式都要重做。
- **现在就实现第二个适配器**：能验证接口，但没有实际需求；只留接缝。
- **只存路径，靠 Forge 的重定向更正路径**：重定向会失效（有人在旧路径新建同名仓库或 fork），有的 Forge 不承诺重定向；仓库删除后又建了同名仓库时，只存路径会悄悄跟到新仓库上。主流 Forge 都有改名后不变、可按 ID 查到当前路径的仓库 ID，所以引用存 ID。
- **每次读写前先单独定位**：最稳妥，但每次读写都多一个串行往返，只为很少发生的改名和转移。
- **把定位移到绑定层，按后台节奏确认**：两次确认之间有空窗，空窗里改名后旧路径上换成另一个仓库时，写入可能落到那个仓库上。
- **等接自建实例时再加主机**：那时要再改一次存储格式，已有绑定都要重新绑定。

## Consequences

- 仓库改名或转移后，下一次从 Forge 读取时绑定会跟到新路径；派发记录按仓库 ID 匹配，换路径后仍然显示。
- 绑定路径没变时，一次读取只调用一次 Forge CLI。
