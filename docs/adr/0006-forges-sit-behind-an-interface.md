# Forge 藏在接口后面，每个 Forge 一个适配器

仓库绑定、issue 与合并请求视图、派发都要读写 Forge。工作台只通过一个与具体 Forge 无关的 **Forge 接口**使用它，每个 Forge 一个适配器，放在一张封闭的表里（与 Agent 类型状态适配器的表同一种做法）。接入新的 Forge 只新增一个适配器。

- **仓库引用 = Forge ID + 仓库路径**。路径是该 Forge 自己的仓库路径，层级因 Forge 而异，适配器之外不拆分它。仓库绑定和派发记录都存这两项。
- **领域形状**：接口只返回领域形状，命名与具体 Forge 无关，不暴露 CLI 的输出格式。
- **四类失败**：未安装、未登录、无法访问、暂时性失败，都带上 Forge 返回的原文；怎样呈现和恢复由适配器提供。
- **能力声明**：Forge 之间的功能差异由适配器声明，Forge 没有的能力 UI 不显示。
- **默认 Forge**：未绑定的项目从默认 Forge 列出可绑定的仓库；出现第二个适配器时，再决定用户怎样选择。

## Considered Options

- **直接对接单一 Forge**：接口更简单，但仓库引用、失败类型和命名都会带上那个 Forge 的形状，接第二个时要改存储格式，而编码规范不写迁移代码。
- **现在就实现第二个适配器**：能验证接口，但没有实际需求；只留接缝。

## Consequences

- `projects.sqlite` 里的仓库绑定存 Forge ID 和路径；Forge ID 不在适配器表里时，按存储规则整体读取失败。
