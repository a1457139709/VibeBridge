# Forge 侧边栏的数据归主进程，渲染进程声明视图并订阅

Forge 侧边栏的列表、详情和刷新调度由主进程的一个功能模块持有，它位于 Forge 接口之上（ADR 0006），按 ADR 0007 自己持有状态。渲染进程只声明它在看什么（项目、标签页、筛选、加载更多、刷新、打开的详情），并报告直接操作和派发已经发生；模块决定拉取什么，把结果以领域形状推送给订阅者，渲染进程只渲染推来的结果。

缓存只在主进程内存里，有上限，重启不保留。合并重复的刷新、定时刷新和缓存上限都放在发出 Forge 请求的同一处。

## Considered Options

- **状态留在侧边栏组件里**：组件卸载（收起侧边栏、切换项目）时数据丢失，每次展开都要重新加载；过期响应的丢弃、刷新计数和操作后的刷新散落在各个组件里。
- **渲染进程里的全局 store**：卸载时不再丢数据，但「合并重复刷新」和定时器与发出请求的主进程隔着 IPC，同一次刷新要在两个进程里各算一遍。
- **侧边栏收起时也在后台刷新**：收起时界面上不显示任何东西，后台拉回的数据看不到，展开时又要再拉一次，只是白白消耗 Forge 的限额。等收起状态需要显示变化提示时再决定。

## Consequences

- 主进程多出的负担是一张有上限的内存表；拉取本来就是在主进程里等 Forge CLI 返回，界面渲染仍在渲染进程。
- 渲染进程里没有按页请求、只认最新响应、刷新计数这类数据路径；新的侧边栏视图通过声明视图接入模块。
- 定时刷新和合并重复刷新由控制时间的单元测试证明（ADR 0005）。
- 修改或解除仓库绑定时，模块立即丢弃该项目的缓存。
