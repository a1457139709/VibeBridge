# 测试替身和测试工具只替代外部，并写明各自证明不了什么

ADR 0005 规定测试怎样做出确定的判定。这里记下各个测试工具和替身为此做的具体决定，以及每种环境证明不了的东西。

## CLI 替身（`tests/fixtures/`）

- Claude、Codex、pi 的 CLI 替身只模拟外部 CLI：读取它们各自的会话设置或启动参数，按原生机制执行命令 hook 或加载扩展。它们不知道工作台的上报协议。
- Codex 替身像 Codex 一样，hook 失败或超时不会中止事件；替身把它报告为 `HOOK-FAILED` 或 `HOOK-TIMEOUT`，测试能看到原因而不是干等。每个 hook 在自己的进程组里运行，超时时连同 shell 启动的东西一起停掉；`close` 事件在 hook 最后的输出之后，所以输出先于 ACK 到达。
- macOS 可能阻塞同步的 TTY 写入者，信号处理 fixture 仍要保持响应（`interactive.cjs`）。

## 单元测试

- 测试控制时间：`ProcessingStatus` 启动的任何计时器都在 tick 时触发（`processing-status.test.ts`）。
- 进程内上报器由测试充当传输层，每条上报由测试交付。没有上报等待 I/O，所以排队的回调跑完后，能发的上报都已发出。pi 的 `/reload` 会在同一进程里加载扩展模块的新副本，而替身的 import 缓存会复用同一个模块，所以测试自己加载每个副本（`pi-reporter.test.ts`）。

## 组件测试（jsdom，`tests/components/`）

- jsdom 没有布局、帧、媒体查询、指针捕获、原生模态 UI 和 `AnimationEvent`。支持代码只模拟需要存在的东西：观察者从不报告，媒体查询从不匹配，帧只在测试运行时才跑，模态框只模拟打开和关闭的 DOM 契约，`animationend` 用不带前缀的事件名。因此组件测试证明不了焦点时机、动画、滚动、顶层渲染和指针必须在哪里。需要几何的测试给布局区域固定的 800×600 和各面板按内联位置分得的份额，只证明放下之后做了什么。
- preload API 是组件的外部边界：意外的调用直接失败，不默默返回宽松的默认值（`support/workbench.ts`）。

## desktop 套件（`tests/desktop/`）

- Electron 的 `button` 标识变化的那个按钮，移动时用修饰键带上按住的按钮，Chromium 才保留指针捕获。原生输入派发是异步的：松开之前先观察到捕获和预览，开始下一次拖动之前要等到调整已保存。
- 合成按键触发不了 Edit 菜单，所以 Command+V 在按键之后由测试执行粘贴，Command+C 只验证不发送任何东西给 Agent。回显的 CSI u 会恢复光标、覆盖之前的行，所以在刚清空的屏幕上选择。按键之后写一个结尾标记，证明它的每个字节都已到达，因为 PTY 的读取可能把它们合并。
- 测试和工作台以同样方式观察屏幕；观察者按创建顺序收到通知，测试的观察者报告时，工作台自己的观察者已经看到同一变化。屏幕不可见时渲染暂停，持有的空闲回调保留之前的尺寸，模拟繁忙的主线程。
- xterm 在终端调整尺寸时重新测量字符宽度，不到一个像素的差异可能让列数少一列，断言允许少一列。全角标点被挤压时后面的文字偏移约 0.8 个单元格，断言用四分之一单元格的容差吸收亚像素取整。
- 证据单独截取：坏掉的渲染进程可能无法检查 DOM，原生画面仍然有用；从不打开报告或图片查看器。断言失败后也让产品执行正常的运行清理。渲染进程挂起时可能永远不回答查询，`until` 的超时仍要报告。

## 检查脚本（`scripts/`）

- `check-test-waits.mjs`：`until()` 的轮询间隔是检查条件的频率，不是固定时长的等待；fixture 替代 Agent CLI 和进程，它们的计时器是测试驱动的行为；desktop 套件在字符串里运行渲染进程代码，所以字符串里的脚本也要检查。
- `check-staged-file-size.mjs`：关闭重命名检测，这样重命名和复制的目标也被检查；符号链接和子模块不含编写的文件内容，跳过；同时使用暂存区里的属性，未暂存的排除规则不能改变结果；blob 大小从索引的对象 ID 读，从不读工作区文件。
- `test.mjs`：从 Git hook 里运行时，`GIT_*` 变量指向本检出的索引和目录；测试创建自己的仓库，所以清掉这些变量。
