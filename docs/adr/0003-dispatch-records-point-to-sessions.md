# 派发记录指向会话而非面板，新面板的记录等会话出现才写下

同一个面板会因 `/clear`、`/resume` 先后承载多个会话，所以派发记录只追加地存下 issue、时间、Agent 类型、送出的指令和接手会话的会话 ID，不记面板。查看时按会话找当前正处在该会话上的面板，找不到就只显示记录。派发到新面板时，等它报出第一个会话才写下记录；在这之前运行实例就结束了的话，不留记录。会话 ID 只用来查找和定位，不拿来恢复会话，因此不违背「不持久化会话恢复标识」。

## Considered Options

- **记面板**：面板换了会话之后，旧 issue 仍然显示这个面板的状态，指向的已经不是接手那次派发的对话。面板关闭或重开应用后，记录也就没有了指向。
- **面板和会话都记**：要定义两者不一致时以哪个为准，而界面上能用来定位的只有「此刻处在该会话上的面板」，记面板没有增加信息。

## Consequences

- 在面板里 `/clear` 或 `/resume` 之后，之前派发过的 issue 不再显示这个面板的状态。
- 派发记录写入 `projects.sqlite`，以后改成指向面板时，已有记录缺少面板信息，且编码规范不写迁移代码。
- 运行实例管理要知道每个运行实例当前的会话 ID，各 Agent 类型的状态解释器都要报告它。
