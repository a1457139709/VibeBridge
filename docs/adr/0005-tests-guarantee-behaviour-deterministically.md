# 测试是行为的保障，判定只取决于行为是否成立

测试是代码行为的保障。每个测试规定一项行为，并且对同一份代码，在任何机器、任何负载下都给出同一个判定。判定只取决于这项行为是否成立，与执行快慢无关。在真实环境里等多久都证明不了某事不会发生，所以这类断言放进由测试控制输入和时间的单元测试。

- **分层**：能用单元测试证明的行为，就写成单元测试；组件测试负责界面交互。desktop 套件只覆盖必须有真实 Electron、操作系统或 PTY 才能测的行为：原生输入、真实窗口几何和拖拽、进程生命周期、重启后的恢复，以及进程之间的连线。
- **各层写明自己证明不了什么**：组件测试的环境没有布局、帧和原生 UI，证明不了焦点时机、动画、滚动和指针落点，这些行为放进 desktop 套件。
- **替身只替代外部**：Agent CLI 和 Forge CLI 的替身只模拟外部程序本身，按它们的原生机制运行，不知道工作台的上报协议。组件测试里，渲染进程与主进程之间的接口是外部边界，意外的调用直接失败，不默默返回宽松的默认值。
- **不为测试增加产品功能**：产品代码里不加只供测试使用的接口，例如表示「已稳定」的查询。测试用已有的状态快照、替身查询和单元测试来达到确定性。
