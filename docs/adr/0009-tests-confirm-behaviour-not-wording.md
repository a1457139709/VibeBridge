# 测试确认程序的行为，不确认界面上的文字

VibeBridge 是界面和程序合在一起的应用，界面展示的是程序的状态。前端测试的惯例按用户看到的文字来定位、等待和断言，这样做等于把文案当成了契约。可是文案只是状态的一种表述，措辞、语言、排版都会变，程序的行为却没有变。因此测试到行为所在的地方去确认行为：

- **测试确认程序的行为**：状态变成了什么、产出了什么数据、向外发出了什么请求。界面上显示的文字不作为确认的依据。
- **判断和推导写成可以直接调用的逻辑**：输入和结果都是结构化的，界面只负责展示结果。界面上的行为因此可以不经过界面就得到确认。
- **失败表达成结构化的信息**：写明是哪种失败，带上相关的数据。给用户看的文字在展示时由这份信息生成。
- **界面测试只确认界面和程序之间的连接**：找界面元素靠语义和文字的标识，不靠具体措辞。
- **只有当行为本身就是"向用户展示某件事"时，测试才看界面**：确认的是展示了哪一件事，不确认措辞。
- **本地化的测试只确认每种语言的结构完整，也不确认措辞**：每种语言都有全部消息，每条译文的占位符与英文相同，带信封的消息还原出来的文字等于该语言对同一消息 id 的译文。这些检查遍历所有语言，增加一种语言不需要新增测试；措辞的对错交给翻译审阅。

这条原则延续了 ADR 0005 的要求：测试的判定只取决于行为是否成立。

## Consequences

- 修改文案、调整措辞、增加语言，都不会让行为测试失败；测试失败时，指向的是行为出了问题。
