# Forge 侧边栏显示 Forge 给出的结论，一次请求取回，截断处说明还有多少

Forge 侧边栏用来扫一眼 issue 和 pull request 的状态，再决定交给哪个 Agent；不复刻 Forge 的完整视图，完整内容由 Agent 通过 Forge 的 CLI 自己读，或者用户点链接去 Forge 上看。因此侧边栏的每个视图用一次 Forge 请求取回它要显示的东西：Forge 返回的字段能回答的问题，直接显示那个字段，不自己推导；Forge 没有给出的，才自己算。列表在这一次请求里取到上限，超出的部分显示 Forge 给的总数并附 Forge 链接，不靠分页补齐；只有缺了会影响用户能做什么的列表才多发请求取完。

- 评论：取最新的一批，时间线顶部提示前面还有多少条并链接到 Forge。pull request 的评论和带正文的 review 合在同一条时间线上。
- review：只显示 Forge 的结论。
- 检查：列出单个检查，按 Forge 返回的顺序，每项显示 Forge 的原始状态或结论（例如超时、已取消、启动失败，而不是归并成通过和失败两类）、是否必需、耗时和链接；列表上方显示 Forge 的整体状态和各状态的完整数量。
- 能不能合并：直接显示 Forge 给出的合并状态和原因，不从检查和 review 自己推导。
- 仓库标签：用于筛选，缺了就选不到，所以例外地取完。
- 子 issue：列出一批，超出时用 Forge 给的总数提示还有多少个。

## Considered Options

- **分页取完每个列表**：侧边栏变成 Forge 视图的复刻；一次刷新可能发出多次请求，定时刷新时（ADR 0008）消耗的 Forge 限额随列表长度增长，分页之间数据还可能变化。用户在侧边栏上要的是结论，长列表在 Forge 上或交给 Agent 读更合适。
- **只设上限、不提示**：超出的部分静默丢失，看起来完整，其实不完整；检查很多时，合并阻塞原因可能漏掉一项失败的必需检查。
- **只显示检查的整体结论，不列单个检查**：用户要据此判断失败是环境问题（超时、取消、启动失败）还是代码问题，再告诉 Agent 怎么处理，只有整体结论不够。

## Consequences

- 新的 Forge 适配器只要给出各自 Forge 的原始结论。
- 新的侧边栏视图按同一原则设计：先看 Forge 的一次返回里有没有现成的结论和总数，没有才自己算。
