# 渲染进程立即显示意图，输入只去用户明确指定的地方

渲染进程里，快照、IPC 回应、DOM 事件和动画的到达顺序都不受控制。下面这些决定保证界面及时反映用户的操作，而键盘输入永远不会落到用户没有指定的终端上。

- **布局和偏好乐观显示**：侧边栏的开关和宽度、面板拖放，操作后立即显示，不等保存回来；保存失败就回到主进程最近存下的状态。较新的操作替换待定的操作，快照不会替换待定操作的预览。
- **Forge 上的直接操作不乐观显示**：关闭、重开、合并成功后，等主进程推来 Forge 此后的状态再显示。
- **每个快照到达就绘制，不合并**：合并两次快照可能藏住一次回到上上次布局的保存。
- **键盘输入只去用户明确指定的目标**：为了让工作区可用而显示的后备视图，不是输入目标；面板显示了但还没有输入接收者时，键盘命令不能让输入留在之前的终端上。快照变化可以更新显示的选择，但当某个控件或列表拥有键盘时，只有明确的定位才能拿走焦点。迟到的定位结果可以改变快照，但只有仍然有效的那次操作能安排焦点。
- **窗口只限制区域怎样绘制，从不改变它们记住的宽度**：窗口变窄时，最后调整的区域保持宽度，其他区域画窄些。
- **隐藏的面板保持挂载**，终端保留屏幕、选择和输入焦点。
